## 一个完整（功能 + UI）插件的组成

要开发一个同时有后端功能和前端 UI 的完整插件，需要以下部分：

### 架构图

my-plugin/

├── package.json          # dsh.bundle manifest + dsh.client manifest

├── cordis.patch.yml      # 声明要插入的 cordis 行

├── src/

│   ├── index.ts          # Host 半：apply() 注册 tool、service 等

│   ├── invariant.ts      # 运行时不变量

│   └── client/

│       ├── index.ts      # Client 半：apply() 注册 React 组件到 slot

│       └── MyToolView.tsx # React UI 组件

└── tsdown.config.ts      # 打包配置

### 第一部分：Host 插件（后端功能）

*// src/index.ts*

import type { Context } from '@deepseek-ai/cordis'

import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'my-feature'

export const inject = ['tools']

export function apply(ctx: Context) {

  ctx.tools.register(defineTool({

​    name: 'my_tool',

​    description: 'Does something useful.',

​    parameters: { */\* ... \*/* },

​    output: { schema: { type: 'string' }, render: (_a, v) => [{ type: 'text', text: v }] },

​    async execute(args) { return 'result' },

  }))

}

### 第二部分：Client 插件（前端 UI）

*// src/client/index.ts*

export const inject = ['slots']

export function apply(ctx) {

  ctx.slots.inject('tool.call.toolview', () =>

​    ctx.slots.register({

​      name: 'tool.call.toolview',

​      key: 'my_tool',  *// 匹配 tool name*

​    }, MyToolView)

  )

}

### 第三部分：Cordis 配置层

*# cordis.patch.yml*

\- insert:

​    \- id: my-feature

​      name: my-plugin-package-name

### 第四部分：Package.json

{

  "name": "dsh-my-plugin",

  "dsh": {

​    "bundle": { "patch": "./cordis.patch.yml" },

​    "client": { "platform": "web" }

  }

}

## 4. 三层组合（Composition）机制

整个 dsh 的配置加载是分层叠加的：

空根

 └─ ① dsh-base (cordis.patch.yml)         ← 共享核心：LLM、session、tools 注册表...

​     └─ ② dsh-web-app (cordis.patch.yml)   ← Web 表面：HTTP server、浏览器组件花名册

​         └─ ③ 你的插件 (cordis.patch.yml)   ← 你的 tool + UI

​             └─ ④ profile cordis.patch.yml  ← 用户本地覆盖

​                 └─ ⑤ --patch overlays      ← 临时覆盖

文档中说明了优先级：

打包与插件安装.mdLines 109-114

生效配置在空根之上按以下顺序逐层组合：

1. profile 的 `dsh.profile.bundles` 列表所列的各个组合包 patch，按列表顺序——先是 `@deepseek-ai/dsh-base`，然后是每个已安装组合包，按其加入顺序。
2. profile 自己的 `cordis.patch.yml`。
3. home 级的 `$DSH_HOME/cordis.patch.yml`——各 profile 共享的机器本地偏好。
4. 每个 `--patch <path>` overlay，按 argv 顺序。

## 5. 打包与安装

### 开发阶段：用 --patch overlay

pnpm dsh web --patch ./my-plugin/cordis.yml

### 正式打包：创建组合包（Bundle）

打包与插件安装.mdLines 30-38

{

  "name": "dsh-hello-plugin",

  "version": "0.1.0",

  "type": "module",

  "main": "index.js",

  "files": ["index.js", "cordis.patch.yml"],

  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }

}

### 安装到 Profile

*# 从本地路径安装*

dsh plugin --profile demo add ./my-plugin

*# 从 GitHub 安装*

dsh plugin --profile demo add github:you/my-plugin

*# 从 npm 安装*

dsh plugin --profile demo add my-plugin-name

安装后 profile 的 `package.json` 自动记录你的包到 `dsh.profile.bundles` 列表中。

### 三种分发形式

| 方式        | 命令                             | 是否需要构建授权                                      |
| :---------- | :------------------------------- | :---------------------------------------------------- |
| npm 发布    | `dsh plugin add your-package`    | 不需要                                                |
| tarball     | `dsh plugin add ./xxx.tgz`       | 不需要                                                |
| GitHub 源码 | `dsh plugin add github:you/repo` | 需要用户在 `pnpm-workspace.yaml` 中授权 `allowBuilds` |

## 总结

| 概念          | 含义                                                   | 对应你的理解                  |
| :------------ | :----------------------------------------------------- | :---------------------------- |
| 插件 (Plugin) | 导出 `apply(ctx)` 的 TS 模块，是一切的基础             | 不仅是"功能逻辑"，UI 也是插件 |
| Tool          | 通过 `defineTool` 注册的 AI 可调用工具，是 host 端功能 | 不是 UI，是后端能力           |
| Host          | Node.js 端，执行真正的业务逻辑                         | 你说的"后端"，正确            |
| Client        | 浏览器端 React 组件，通过 slot 系统组合                | 你说的"前端/web"，正确        |
| cordis.yml    | 声明插件加载、配置、依赖关系                           | 环境配置，正确                |
| Bundle        | 带 `dsh.bundle` manifest 的 npm 包，携带一个 patch 层  | 打包分发单元                  |
| Profile       | `$DSH_HOME/profiles/<name>` 下的可启动组合             | 用户的运行环境                |

简单来说：插件 = 最小单元（万物皆插件），Tool = 一种特定的 host 插件（给 AI 用的能力），UI = 另一种 client 插件（给人看的界面）。一个完整的功能需要 host 插件实现逻辑 + client 插件实现展示，通过 cordis.patch.yml 声明组合关系，通过 `dsh.bundle` manifest 打包，通过 `dsh plugin add` 安装。
