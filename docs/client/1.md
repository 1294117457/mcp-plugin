## 1. dsh 拉起时怎么拿到 `ctx`

`@package.json (57-70)` 的 `dsh.client` 块就是给 dsh loader 看的"启动说明书"：

```
"dsh": {
  "client": {
    "platform": "web",
    "inject": ["@deepseek-ai/dsh-client-runtime", "..."],
    "immediately": false
  }
}
```

dsh loader 流程：

1. 在 `cordis` 树里建一个 `client` 节点
2. `platform: "web"` → 它决定 loader 会去找 `lib/client.js`（tsdown 输出的产物）
3. `inject: [...]` → loader 按顺序把这些 client 包（`@deepseek-ai/dsh-client-runtime`、`@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-settings`、`@deepseek-ai/dsh-client-locale`、`...`）注入并 `ctx.effect` 进 cordis 树
4. 那些包各自往 `ctx` 上挂服务：`ctx.slots`、`ctx.locale`、`ctx.effect`、`ctx.connection` 等都是它们 register 出来的
5. 所有 inject 完成之后，loader 才把我们的 bundle 加载进来，调用 `apply(ctx)`

所以 `apply(ctx)` 收到的 `ctx` 就是这个已经被宿主 + 那些 client 包"装满了服务"的 cordis 对象。

## 2. `slots.inject` 是什么

`@index.ts (56-68)`：

ctx.slots.inject('settings.section', () =>

  ctx.slots.register({...}, McpSection)

)

`ctx.slots` 是 `@deepseek-ai/dsh-client-ui-slots` 注册的服务，它做了两件事：

- 内置一个注册表，记录所有 "我要往哪个 slot 名里塞什么"
- 提供 `slots.inject(slotName, factory)`：把这个 bundle 的"我要贡献给某个 slot 的内容"登记进那张表

`'settings.section'` 这个 slot 名不是我们起的——是 `@deepseek-ai/dsh-client-ui-settings` 这个宿主包预先声明的：它定义了"dsh 设置弹窗里有一个叫 `settings.section` 的槽位，需要多个贡献者依次填入"。

## 3. `register(...)` 怎么把 UI 塞进去

`@index.ts (57-67)` 里 `register` 拿两样东西：

- 元数据（id / order / label / locale / inject）：告诉 slots 系统"我在这个 slot 里是一条叫 `mcp` 的 section，排序 20，标签叫 `nav`，同时需要把 `store` + `t` 通过 `inject` 字段先拿到再传给组件"
- 组件 `McpSection`：当设置弹窗打开时，宿主会从注册表里把所有 section 组件按 `order` 排序，依次渲染

所以 `meta.name = 'settings.section'` 表示"我声明要贡献给 settings.section 这个 slot"，`id = 'mcp'` 是这一条的内部 id（同一 slot 多个贡献者要彼此不同）。

## 4. 完整链路图

```
dsh 启动
  │
  ├─ 读 packages/*/package.json 里的 dsh.client.inject 列表
  │     │
  │     ├─ 把 dsh-client-runtime 加载进来 → ctx.effect / ctx.disposal 等
  │     ├─ 把 dsh-client-ui-slots 加载进来 → ctx.slots
  │     ├─ 把 dsh-client-ui-settings 加载进来 → 声明 'settings.section' 这个 slot
  │     ├─ 把 dsh-client-locale 加载进来 → ctx.locale
  │     └─ ...
  │
  ├─ 加载我们的 bundle（lib/client.js）→ 调 apply(ctx)
  │     │
  │     ├─ ctx.effect(() => ctx.locale.register(NS, {zh, en}), '...')
  │     │     → 把中英文字典塞进 locale 表
  │     │
  │     └─ ctx.slots.inject('settings.section', () =>
  │          ctx.slots.register(
  │            {name: 'settings.section', id: 'mcp', order: 20, ...},
  │            McpSection  ← 组件本体
  │          )
  │        )
  │           → 在 'settings.section' slot 里登记一条 id='mcp' 的 section
  │
  └─ 用户点开设置弹窗
        └─ dsh-client-ui-settings 读 ctx.slots 注册表
              → 把所有 id='mcp' / 'general' / 'models' 等 section 按 order 排序
              → React 渲染弹窗，渲染到 'mcp' 那一条时把 McpSection 渲染出来
              → 渲染前先调 inject: () => ({ store, t })
                   → 拿到 store（McpStore 实例）和 t（绑定到 NS 的翻译函数）
              → 调 McpSection({store, t, ...})
```



## 5. 几个关键点

| 概念                              | 谁定义                                     | 我们用什么                                                  |
| :-------------------------------- | :----------------------------------------- | :---------------------------------------------------------- |
| `ctx`                             | cordis 根                                  | `apply(ctx)` 参数                                           |
| `ctx.slots`                       | `@deepseek-ai/dsh-client-ui-slots`         | `ctx.slots.inject / register`                               |
| `'settings.section'` 这个 slot 名 | `@deepseek-ai/dsh-client-ui-settings` 声明 | 我们只是"贡献者"                                            |
| 排序、标签、locale ns             | 我们自己定                                 | `order: 20`、`label: () => t('nav')`、`NS = 'settings.mcp'` |
| `id: 'mcp'`                       | 我们自己定                                 | 给这条 section 在 slot 里的内部唯一 id                      |
| `McpSection` 组件                 | 我们写                                     | 宿主渲染时调用                                              |

换句话说：`ctx.slots.inject('settings.section', ...)` 不是我们"抓起"了 settings.section，而是我们向宿主已声明的 settings.section 槽位"提交"了一份内容。宿主那边（`@deepseek-ai/dsh-client-ui-settings`）才是这个 slot 的消费者。多 bundle 都可以同时往这个 slot 投内容，order 决定渲染顺序。
