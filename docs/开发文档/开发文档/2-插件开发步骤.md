# 插件开发步骤

> 本篇是**实战手册**——以 `my-dsh-mcp-settings` 项目为样例，按时间顺序把"开发一个 dsh 外部插件"涉及的所有步骤说完。
> 假设读到本篇时**已经读过 `1-dsh架构.md`**，对 cordis / Loader / patch / 双 bundle 等概念有基本印象。

## 1. 准备工程骨架

### 1.1 创建独立 npm 包

dsh 插件跟 dsh 主仓库**完全分离**——它是普通 npm 包，目录随便放，常用约定：

```
my-dsh-plugin/mcp/
├── package.json
├── tsconfig.json          # host 端 tsc 配置
├── tsdown.config.ts       # client 端打包配置
├── cordis.patch.yml       # host 注册模板
├── README.md
├── src/
│   ├── index.ts           # ★ host 入口
│   ├── config-schema.ts   # （可选）共享 schema
│   ├── webserver-routes.ts
│   ├── ...
│   └── client/
│       ├── index.ts       # ★ client 入口
│       ├── *.tsx / *.ts / *.module.css
│       └── ...
└── lib/                   # 编译产物（git ignore）
```

> ⚠ 放在外面 `/home/dustp/codes/my-dsh-plugin/mcp/`，**不要**塞进 `deepseek-harness/` 仓库。后面 `dsh plugin add file:...` 直接吃 tarball，不必放在 workspace 里。

**5 个不能写错的坑**：

| 字段 | 错 | 对 | 错的后果 |
|---|---|---|---|
| `exports["./client"].default` | `"./lib/client/index.js"` | `"./lib/client.js"`（**flat**） | dsh 返回 404 加载 client |
| `dsh.client.platform` | 缺失或写成其他 | `"web"` | client bundle 整体跳过 |
| `dsh.client` vs `dsh.bundle.client` | 嵌套在 `bundle` 下 | 平级 `dsh.client` | 见 `my-dsh-mcp-修复总结.md` 第 1 节 |
| `files` 名单 | 写成 `lib/**/*.js` | `["lib", ...]` | `pnpm pack` 出的 tarball 漏 `lib/client.js` |
| `peerDependencies` | 漏一个 dsh 包 | 全列 | 启动时 cordis 解析失败 |

## 2. host 入口：从 4 个导出开始

`src/index.ts` 是 host 在 Loader 里的入口。cordis 协议规定这一包得 **named export** 这 4 个：

```ts
// my-dsh-plugin/mcp/src/index.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-dsh-mcp-settings'           // ★ cordis 用这个 id

/** inject = 我要等谁先启动；这里 'webServer' 是 dsh 自己挂的 HTTP carrier */
export const inject = ['webServer'] as const

export function apply(ctx: Context): void {
  // 你的初始化放这里
  // 返回一个 dispose（或用 ctx.effect 注册到 teardown 链）
  const dispose = registerSomething(ctx)
  ctx.effect(
    () => [dispose] as Iterable<() => void>,
    'my-dsh-mcp-settings: dispose something',
  )
}
```

**4 个导出对应 cordis 协议**：

| 导出 | 类型 | 含义 |
|---|---|---|
| `name` | `string` | 插件 id，全局唯一，对应 `cordis.patch.yml` 里的 `name` |
| `inject` | `string[]` | 等哪些 service 先起来 |
| `apply(ctx)` | `(ctx) => void` | 实际逻辑；返回值或返回 `ctx.effect(...)` 注册 cleanup |
| `dispose`（间接） | `() => void` | 通过 `ctx.effect(...)` 链注册 |

我们的 mcp-settings 里 `apply` 做的是：调 `registerMcpRoutes(ctx)` 注册 HTTP 端点。

### 2.1 cordis.patch.yml：给 Loader 看的注册模板

```yaml
# my-dsh-plugin/mcp/cordis.patch.yml
- insert:
    - id: my-dsh-mcp-settings          # ★ cordis fiber id
      name: my-dsh-mcp-settings        # ★ 要跟 package.json#name 一致 = npm 包名
      apply: ./lib/index.js            # ★ Loader 调这个文件取出 apply(ctx)
```

`tsc -p .` 编出 `lib/index.js` 后，Loader 调它得到 `apply` 函数。

> 注意 `name` 字段在 patch 里是 npm 包名，跟 package.json 的 `name` 字段必须严格相等。

## 3. 写 host 端逻辑（路由 + 文件操作）

### 3.1 注册 HTTP 端点

我们的项目有 4 类路由：

```ts
// webserver-routes.ts 简化示意
export function registerMcpRoutes(ctx: Context): () => void {
  const disposers: (() => void)[] = []

  disposers.push(ctx.webServer.register({
    kind: 'exact',
    path: '/api/mcp/list',
    handler(_req, res) { /* ... */ },
  }))
  // ... add / remove / status / tools / test

  return () => { for (const d of disposers) d() }
}
```

**协议**：
- `handler(req, res)`——`req` 是 Node `IncomingMessage`，`res` 是 `ServerResponse`。
- 返回 `void | Promise<void>`；超长操作可以 `void readJsonBody(req).then(...)`，记得 `.catch()` 兜底。
- `disposers` 是路由反注册数组——插件 disable 时 loop 调用清空。

### 3.2 原子写 patch 文件

所有"改 plugin 持久态"的操作都走 patch 文件。我们的 `patch-store.ts` 重点：

```ts
// 关键点
function writePatchLayers(p: string, layers: PatchOptions[]): void {
  const composed = applyEntryPatches([], layers, () => { /* silent */ })
  const text = yaml.dump(composed, { schema: entryListSchema, noRefs: true })
  mkdirSync(dirname(p), { recursive: true })
  const tmp = `${p}.tmp`
  writeFileSync(tmp, text, 'utf8')
  renameSync(tmp, p)        // ← tmp + rename 是关键，避免半写文件触发坏 HMR
}
```

原则：
- 必须 atomic（tmp 文件 + `renameSync`）。
- 用 `applyEntryPatches` 而非 `yaml.dump`，因为 patch 文件可能含 `!!js/function` 用户自定义节点。
- 读用 `yaml.load(text, { schema: entryListSchema })`，写也用同一个 schema。

### 3.3 跨配置中心化读 `process.env.DSH_PROFILE`

web profile 在哪个 profile 名下启动，由 `DSH_PROFILE` 决定。我们这里用 `process.env.DSH_PROFILE`，**不要**走 `ctx.env`，因为后者需要 `launchEnvironment` inject 额外的依赖。

```ts
function resolveProfileName(_ctx: Context): string | null {
  const fromProc = process.env['DSH_PROFILE']
  return typeof fromProc === 'string' && fromProc.length > 0 ? fromProc : null
}
```

## 4. client 入口：从 4 个导出 + 5 个 props 开始

`src/client/index.ts` 同理，但**协议不同——注入的是 `ClientContext`**：

```ts
import type { ClientContext } from '@deepseek-ai/dsh-client-runtime/client'

export const name = 'my-dsh-mcp-settings:client'    // 跟 host 不冲突就行

export const inject = ['slots', 'locale'] as const   // client 端用的 service

export function apply(ctx: ClientContext): void {
  // 1. 注册文案
  ctx.effect(
    () => ctx.locale.register('settings.mcp', { zh, en }),
    'my-dsh-mcp-settings: register locale dictionaries',
  )
  const t = ctx.locale.bind('settings.mcp')

  // 2. 建 store（不放在模块顶层！）
  const store = new McpStore()

  // 3. 等 settings.section slot 起来 → 注册自己
  ctx.slots.inject('settings.section', () =>
    ctx.slots.register(
      {
        name: 'settings.section',
        id: 'mcp',
        order: 20,                       // 0=General 10=Models 20=MCP
        label: () => t('nav'),
        locale: 'settings.mcp',
        inject: (): McpSectionInjected => ({ store, t }),
      },
      McpSection as (props: McpSectionProps) => ReactNode,
    ),
  )
}
```

**5 条约束**（这是"bundle discipline"，写在 `packages/client/AGENTS.md` 里）：

1. **不在模块顶层持有 `ctx` 句柄**——客户端多实例会复用同一个 bundle，所有共享资源都得包到 `apply()` 里 `new` 出来。`new McpStore()` 是反例正解。
2. **组件不直接 import `ctx`**——只能通过 slot 的 `inject` 工厂下发 `{ store, t }`。
3. **locale 用单 namespace**——别分裂成几个 ns，dsh 的 i18n 合并逻辑按 `McpKey` type 校验。
4. **slot 注册用 `slots.inject(name, factory)`**——等 owner 起来再调 `slots.register`，否则 race condition。
5. **CSS 必须 `.module.css`**——CSS Modules 走 lightningcss 内联进 bundle，传统 CSS 不会注入（见 4.2）。

### 4.1 client 端 fetch 数据

UI 跟 host 通信**只走 HTTP**——`fetch('/api/mcp/list')` 这种。客户端 store 模板：

```ts
// mcp-store.ts 简化
import { createSnapshotStore } from '@deepseek-ai/dsh-client-runtime/client'
import { useSyncExternalStore } from 'react'

export class McpStore {
  readonly store = createSnapshotStore<McpState>(INITIAL)

  async load(): Promise<void> {
    this.store.update((s) => { s.status = 'loading' })
    const r = await fetch('/api/mcp/list').then((res) => res.json())
    this.store.update((s) => { s.entries = r.value; s.status = 'ready' })
  }

  useSnapshot(): McpState {
    return useSyncExternalStore(
      (cb) => this.store.subscribe(cb),
      () => this.store.getSnapshot(),
    )
  }
}
```

要点：
- `SnapshotStore` 是 dsh runtime 提供的——比手写 pub/sub 省事，且兼容 React 18 strict mode。
- `useSyncExternalStore` 绑在 instance 上，不要绑在 class 上。
- 一次性 `load()` 在 `useEffect(() => { if (status === 'idle') load() }, [])` 启动；后续刷新走事件驱动（Test / Add / Remove 各自 fetch）。

### 4.2 CSS Modules：通过 lightningcss 进 bundle

```css
/* McpSection.module.css */
.button { padding: 8px 16px; border-radius: 4px; }
.buttonPrimary { background: var(--color-primary); }
```

`tsdown.config.ts` 已经装好 lightningcss plugin：`import css from './McpSection.module.css'` 时，`css.button` 等的**已经 compile 成 hashed 名字**，并且 `<style data-plugin-css="...">` tag **自动 inject**。所以**不需要**手动 `import './McpSection.module.css'`。

## 5. CSS-in-bundle 跟 tsdown 配置

### 5.1 tsdown.config.ts 必须的 6 个开关

```ts
import { defineConfig } from 'tsdown'

export default defineConfig({
  entry: { client: 'src/client/index.ts' },
  outDir: 'lib',
  format: 'cjs',
  platform: 'browser',
  dts: false,
  sourcemap: true,
  clean: false,
  external: [
    'react', 'react/jsx-runtime',
    '@deepseek-ai/cordis',
    '@deepseek-ai/dsh-client-runtime/client',
    '@deepseek-ai/dsh-client-ui-slots',
    '@deepseek-ai/dsh-client-web-react',
    '@deepseek-ai/dsh-client-ui-primitives',
    '@deepseek-ai/dsh-client-ui-attachment',
    '@deepseek-ai/dsh-client-schema-form',
  ],
  define: {
    'process.env.NODE_ENV': JSON.stringify(process.env.NODE_ENV ?? 'production'),
  },
  plugins: [ /* CSS Modules → lightningcss */ ],
  outputOptions: {
    entryFileNames: 'client.js',
    banner: `window.__ModuleLoader__.load({ id: ${JSON.stringify(PLUGIN_ID)}, factory: (require) => {`,
    footer: 'return module.exports; } });',
    intro: 'var module = { exports: {} }; var exports = module.exports;',
  },
})
```

⚠ 关键点：
- `entryFileNames: 'client.js'` ——产物 flat 路径。
- `banner` / `footer` ——这是给浏览器 runtime 吃的钩子，没这两行 client bundle 不会自动注册。
- `external` 必须把 dsh runtime 的几个 npm 包保留为裸 specifier，让 runtime 解析；其他依赖走 `noExternal: () => true` 内联进 bundle。
- CSS Modules plugin 把 `*.module.css` → JS 对象 + 自动注入 `<style>`。

### 5.2 别用 `tsc` 编 client

`tsc -p .` 编出来是 ESM，浏览器加载立刻 syntax error。**client 永远必须 `tsdown`**。

## 6. ambient.d.ts：补 cordis / slots 的类型

`tsc -p .` 编 host 端时，dsh 内部的 `Context.webServer`、`Context.loader`、`ToolRuntime.layers.merge()` 这些**运行时有但 TS 编译期看不到**。`src/ambient.d.ts` 写 declare module：

```ts
import type { Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context {
    webServer: { register(route: {...}): () => void }
    loader: { entries(): Iterable<{...}> }
    tools: { layers: { merge(...): Map<string, unknown> } }
  }
}

declare module '@deepseek-ai/dsh-client-ui-slots' {
  interface LocaleNamespaceMap {
    'settings.mcp': McpKey      // 你注册的 namespace
  }
}
```

> ⚠ 别对已经存在的 slot 重复 declare——owner 包已经在 `client.ts` 里 declare 过了，重复声明会触发 TS2717 "Subsequent property declarations must have the same type"。要消费已有 slot，靠 `import type {} from '<owner>/client'` 让 TS 拉取合并。

## 7. 构建管线：tsc + tsdown

```bash
cd my-dsh-plugin/mcp

# host 端：纯 tsc（Node ESM）
node_modules/.bin/tsc -p .
# 输出：lib/index.js  lib/index.d.ts  lib/webserver-routes.js  ... + *.d.ts

# client 端：tsdown（rolldown bundle）
node_modules/.bin/tsdown
# 输出：lib/client.js  lib/client.js.map
```

> ⚠ **绕开** `pnpm exec`。`pnpm v11` 在执行 esbuild / swc / lightningcss 这类 native build 之前会强制走 `verify-deps-before-run`，对本项目会拦你直接用相对路径。
> 直接走 `node_modules/.bin/...` 一律可过——`tsc` / `tsdown` 都是纯 JS binary。

清重建：

```bash
node_modules/.bin/tsc -p . --build --force  || rm -rf lib && node_modules/.bin/tsc -p .
node_modules/.bin/tsdown --force              || rm -rf lib/client* && node_modules/.bin/tsdown
```

`tsdown --clean` 也会清整个 `lib/`，连 `index.js` 一起干掉——所以**两次构建必须分别跑**。

## 8. 打包 tarball

### 8.1 `pnpm pack` 跟实际需要的不一样

```bash
pnpm pack --pack-destination .
```

如果 `files` 字段在前面配好，这一步会产 `my-dsh-mcp-settings-0.1.0.tgz`，**大部分情况下** OK。偶尔会因为 symlink 算 hash 出错，tarball 实际文件清单只列目录不列文件——这时候直接 `tar`:

### 8.2 兜底用 tar

```bash
cd my-dsh-plugin/mcp
tar -czf my-dsh-mcp-settings-0.1.0.tgz \
  package.json lib cordis.patch.yml README.md

# 验证
tar -tzf my-dsh-mcp-settings-0.1.0.tgz | grep -E 'lib/client|lib/index' 
# 必须看到 package/lib/index.js  package/lib/client.js
```

`tar.gz` 是 npm 安装格式的**等价表示**——`dsh plugin add file:./...tgz` 内部就是解压它。

## 9. 注册到 dsh

```bash
cd /home/dustp/codes/deepseek-harness
node apps/cli/lib/bin.js plugin --profile web add \
  "file:/home/dustp/codes/my-dsh-plugin/mcp/my-dsh-mcp-settings-0.1.0.tgz"
```

`--profile web` 跟 `dsh web` 的 profile 必须一致。检查：

```bash
node apps/cli/lib/bin.js plugin --profile web list | grep my-dsh-mcp
```

注册这一刻 dsh-cli 会：
1. 解 tarball 到 `~/.dsh/profiles/web/node_modules/my-dsh-mcp-settings/`
2. 把包名加到 `~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles`
3. 装 peer deps（如果 `--install`）
4. 立即触发一次 patch 合成 + 启动 host 端 entry

> ⚠ host 端 entry 是**新增**生效，但**当前进程里已加载的** Loader 不会重新扫。要重启 dsh 才能看到新 host 路由。

## 10. 重启 dsh

web profile 的 plugin HMR **没有 full-reload**——client 半边可热，host 半边需重启：

```bash
pkill -f "dsh web" 2>/dev/null    # 静默失败 ok
node apps/cli/lib/bin.js web        # 或 'dsh web' 当 PATH 在
# 监听 http://127.0.0.1:3080
```

可能端口不一样（看 `binName` 配置）——日志里第一行会打印。

## 14. 反模式 / 高频踩坑

| 症状 | 根因 | 修 |
|---|---|---|
| `pnpm pack` tarball 缺 `lib/client.js` | pnpm v11 hash 算错 | 直接 `tar -czf` |
| `pnpm exec tsdown` 卡在"ignored build" | pnpm v11 verify-deps | 直接 `node_modules/.bin/tsdown` |
| bundle 装好但 UI 没 tab | `dsh.client` 写成 `dsh.bundle.client` | 改回 `dsh.client` |
| `/plugins/<id>/client.js` 返回 404 | `exports["./client"].default` 写错路径 | **必须是** `lib/client.js` flat 路径 |
| `tsdown` 出的 ESM 浏览器 syntax error | format 选了 esm | `format: 'cjs'` |
| "保存无反应" | `submitDisabled` 没检查 `command`/`url` 空值 | 加 `missingTransportField` |
| "保存后工具列表没出现" | `status` 字段用错 loader fiber state 编号 | 抄 `phaseFromFiber` 那个 switch |
| "测试连接 timeout 一直挂" | `testMcpConnection` 没有 5s budget | 用 `withTimeout()` 套 promise |
| "browser 控制台 `ctx` undefined" | 组件 import 了 ctx | 删掉，靠 slot inject 工厂传 prop |
| HMR 触发但 fiber 没 dispose | patch 行用了非 `mcp-<serverName>` id | id 必须严格 `mcp-<serverName>` |
