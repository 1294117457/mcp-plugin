## 1. 三条纠正（与前序文档的差异）

### 1.1 HMR **完全可用**，不需要重启 dsh

前序文档（`2.md` §4.4、`3.md` §0）说："web 模式下 HMR disabled，需重启 dsh"。
**错。** 真实代码在 `apps/cli/src/profile-boot.ts:279-294`：

```ts
if (ctx.get('hmr') === undefined) {
  if (ctx.get('timer') === undefined) {
    await ctx.loader.create({ name: '@deepseek-ai/cordis-plugin-timer' })
  }
  await ctx.loader.create({ name: '@deepseek-ai/cordis-plugin-hmr', config: { root: [] } })
}
await watchUserPatches(ctx, {
  binName: NAME,
  filename: composed.profile.patchPath,   // = ~/.dsh/profiles/web/cordis.patch.yml
  compose: composeLive,
})
await watchUserPatches(ctx, {
  binName: NAME,
  filename: homePatchPath(),              // = ~/.dsh/cordis.patch.yml
  compose: composeLive,
})
```

**结论**：

- `web-app` 的 bundle 关掉自己的 `hmr` row，但 cli 在 boot 末尾**自己额外
  mount 一个 `cordis-plugin-hmr`**（`root: []` 只监听配置文件，不接管
  模块热重载——避免 web 的 module-reload 生命周期问题）；
- 然后无条件挂两个 `watchUserPatches`——profile patch + home patch 都生效；
- watchUserPatches 内部走 `hmr.registerConfig`，回调里 `entry.update({ config: { patches } })`，
  cordis Loader 自动 diff entries，**mcp-client 实例自动 dispose/active，工具
  自动注册/卸载**；
- 用户在 UI 点保存 → `patch-store` 原子写 patch 文件 → ~100ms 内 cordis 重构
  → 新 mcp-client 起来 → `ctx.tools.register('mcp__<server>__<tool>', ...)` →
  浏览器端通过 SSE 看到新工具。

**所以"保存无反应 / 重启无变化"的根因** 不是 HMR 不可用，而是你 `patch-store`
写入失败 + UI 没显示错误（两个 bug，今天一并修了）。

### 1.2 mcp-client row 的 `name` 是 npm 包名

`packages/mcp/mcp-client/src/index.ts:543` 内部导出 `name = 'mcp-client'`
（仅用于 cordis 诊断），但 patch 行里 `name` 字段是 **Loader 解析用的
import spec**：`@deepseek-ai/cordis-plugin-loader/lib/index.js:512`：

```js
plugin = this.loader.unwrapExports(
  await this.parent.tree.import(this.options.name, this.getOuterStack))
```

`import('@deepseek-ai/dsh-mcp-client')` 走的是 Node 包解析，跟 `name` 字段
的实际值无关，只跟"它是不是一个能解析到的 npm 名"有关。`examples/mcp-memory/*.cordis.yml`
全用 `'@deepseek-ai/dsh-mcp-client'`，所以 `patch-store` 里

```ts
const MCP_CLIENT_NAME = '@deepseek-ai/dsh-mcp-client'
```

是**正确的**。文档 2.md 里写 `'mcp-client'` 反而错。

### 1.3 client bundle 必须用 tsdown（不是 tsc）

`tsc -p .` 编出 ESM（带 `import/export`），浏览器 `<script src=...>` 加载时
syntax error。tsdown 编出 classic CJS，裹在 `window.__ModuleLoader__.load({ id, factory })` 里。

`tsdown.config.ts` 的 banner / footer / intro 已写死，是上游 `packages/client/tsdown.client.ts` 的复刻。

`exports["./client"]` 必须指 **flat 文件 `lib/client.js`**，不能是 `lib/client/index.js`——
`client-modules` 直接读 `pkg.exports["./client"].default` 拼 `/plugins/<id>/client.js`，
指错路径 dsh 返回 404。

## 2. 这一版改了什么（vs. 之前能跑但 UI 没工具列表的版本）

### 2.1 `webserver-routes.ts`

- ✅ **新增 `/api/mcp/tools`**：遍历 `ctx.tools.layers.merge(undefined, layer => layer.tools)`，
  过滤 `mcp__` 前缀，按 `__` 拆 serverName + rawName，返回 `{ serverName, name, description }[]`。
- ✅ **新增 `/api/mcp/status`**：合并 patch 文件列表（权威 serverName）+ Loader fiber phase
  （运行时状态），返回 `{ serverName, transport, command, url, status }[]`。
- ✅ 把 status / tools 路由单独放在 `registerRuntimeRoutes()`——之前是合并注册，
  现在 `apply()` 调一次，CRUD + runtime 一起挂。

### 2.2 `client/mcp-store.ts`

- ✅ **加了 `tools: Record<string, McpToolEntry[]>` 到 snapshot**——之前 UI 看不到
  tool 列表。
- ✅ **`load()` 改成并行拉 status + tools**，一次 paint；之前要等两次 fetch。
- ✅ **加了 `startPolling(intervalMs = 2000)`**——McpSection useEffect 启动一次，
  2 秒间隔拉一次，**这个轮询是 HMR 可视化的关键**：cordis Loader dispose/active
  触发 `ctx.tools` 变化，UI 在 2 秒内更新。
- ✅ `add()` / `remove()` 成功后 `setTimeout(250ms)` 再 load——给 HMR 一点 settle 时间，
  让新 mcp-client 的 tool 注册跟 patch 写入在同一 paint 显示。

### 2.3 `client/McpSection.tsx`

- ✅ **删了 `noticeRestart`** 的 `<p>`——HMR 是工作的，不需要"请重启 dsh"提示。
- ✅ **改了 intro 文案**——告诉用户"保存后自动生效，几秒内更新工具列表"。
- ✅ **启动时自动开始轮询**（`useEffect(() => store.startPolling(2000))`），
  返回的 disposer 在 unmount 时清理。
- ✅ `submitConfig` 现在把 `state.error` 显式给 UI——之前 `add()` 失败只更新 store
  error 字段，但 UI 没在错误条显示。

### 2.4 `client/McpRow.tsx`

- ✅ **新增可展开工具列表**——右侧 "展开工具 (N)" 按钮，点开后显示每个
  tool 的 `name` + `description`。tool list 来自 `state.tools[serverName]`。
- ✅ 0 个 tool 时不显示展开按钮（避免无意义交互）。
- ✅ 状态徽标（active / loading / failed / pending）保留。

### 2.5 `client/McpForm.tsx`

- ✅ **修 "保存无反应" 的核心 bug**——之前 `submitDisabled = busy || nameInvalid || serverName.length === 0`，
  没检查 `command` 或 `url` 是否空，导致 stdio 提交空 command / http 提交空 url 时
  host 400 但 UI 没反应。现在：
  ```ts
  const missingTransportField = transport === 'stdio'
    ? command.trim().length === 0
    : url.trim().length === 0
  const submitDisabled = busy || nameInvalid || serverName.length === 0 || missingTransportField
  ```
  按钮直接 disabled，UI 一眼能看出哪儿没填。
- ✅ 修了之前的 string replace 调用（locale 类型从 `(key: string) => string` 变成
  `(key: McpKey) => string`，去掉占位符语法）。

### 2.6 `client/locales.ts`

- ✅ 把 `noticeRestart` 改成 `noticeLiveReload`，文案变成"HMR 自动生效，无需重启 dsh"。
- ✅ `expandTools` / `collapse` / `errorLoad` 等键补齐。
- ✅ 改为 `Record<McpKey, string>` 类型（去掉 ICU 占位符，简化）。

### 2.7 `client/McpSection.module.css`

- ✅ `.toolList` / `.toolItem` / `.toolName` / `.toolDescription` 四个新样式
  （在 row 的 grid 中用 `grid-column: 1 / -1` 跨满）。
- ✅ 老的 `.notice` 类留着（warning 黄底）——以后备用。

### 8.2 为什么用 SDK 直探而不是复用 dsh-mcp-client

`@deepseek-ai/dsh-mcp-client` 的 `apply(ctx, config)`：
- 通过 `ctx.effect` 把 serverName 注册到 `activeServerNames` 集合——会**长期占用** namespace
- `startConnection` 持续重连、`syncTools` 持续 reconcile——不能"1 秒退出"
- `createTransport` 是内部 helper（d.ts 里有，js bundle **没有 export**）

探针只关心"能不能 `initialize` + `tools/list`"两件事——直接用 SDK 的 `Client` + `StdioClientTransport` / `StreamableHTTPClientTransport` 即可，不污染持久 namespace。
