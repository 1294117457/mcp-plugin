# 方案：MCP UI → 工具注册到 ctx 的完整闭环

> 本文是 `1.md` / `2.md` 的工程化方案。**不修改代码**，只描述改造路径。
>
> 目标：**用户在 UI 添加一个 mcp server → dsh-mcp-client 实例启动 → 工具自动注册到 ctx → agent 可用**。每一步在哪一层、谁负责、踩什么坑，全讲清。

## 1. 整体流程（用户视角 → 内部机制）

```
┌─────────────────────────────────────────────────────────────┐
│  用户在浏览器 settings → MCP 服务 tab                        │
│  填表单：serverName=memory, transport=stdio, command=memorix │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼ 点击 "保存"
┌─────────────────────────────────────────────────────────────┐
│  Client: McpForm → mcpStore.save(config)                    │
│  → connection.api.mcpSettings.add(config)    (HTTP+SSE)     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Host: McpSettingsGateway.add(config)                       │
│  → PatchStore.add(config)                                   │
│     1. 读 ~/.dsh/profiles/<name>/cordis.patch.yml            │
│     2. 过滤掉同 serverName 的旧 row                         │
│     3. 追加新 row: { id: "mcp-memory", name: "@deepseek-ai/dsh-mcp-client", config } │
│     4. yaml.dump with entryListSchema → 原子写回             │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼ (写盘)
┌─────────────────────────────────────────────────────────────┐
│  Loader: 检测到 patch 文件 mtime 变化                        │
│     - headless profile: HMR 自动 reload                      │
│     - web profile: 当前 HMR disabled，需用户重启 dsh          │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Cordis: 加载新 row (name: "@deepseek-ai/dsh-mcp-client")   │
│  → 调用该 package 的 apply(ctx, config)                     │
│  → @deepseek-ai/dsh-mcp-client 启动                          │
│     1. 校验 serverName 命名空间（不冲突）                    │
│     2. spawn 子进程 memorix serve / 发 HTTP 连接             │
│     3. 走 MCP 协议 → 工具发现                               │
│     4. ctx.tools.register('mcp__memory__save', impl)         │
│     5. ctx.tools.register('mcp__memory__query', impl)        │
│     6. await Promise resolve → plugin activate              │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼ (tools 事件推送到 browser)
┌─────────────────────────────────────────────────────────────┐
│  Browser: agent loop 看到工具列表里多出新条目                │
│  模型可选这些工具 → 用户在对话看到工具调用结果                │
└─────────────────────────────────────────────────────────────┘
```

**关键事实**：

| 环节 | 谁负责 | 你写吗 |
|------|--------|--------|
| UI 渲染 | `McpSection/McpForm/McpRow` | ✅ 你写 |
| Remote API 调用 | `McpSettingsGateway` | ✅ 你写 |
| 写 patch 文件 | `PatchStore` | ✅ 你写 |
| HMR / 重启 | dsh Loader | ❌ dsh 内置 |
| 启动 mcp-client 实例 | `@deepseek-ai/dsh-mcp-client` | ❌ dsh-mcp-client 自己 |
| 工具发现 + 注册 | `@deepseek-ai/dsh-mcp-client` | ❌ dsh-mcp-client 自己 |
| 工具调用路由 | agent loop | ❌ dsh 内置 |

## 2. 你作为插件作者，**不需要**做什么（重要！）

### 2.1 不需要写"工具注册到 ctx" 代码

`@deepseek-ai/dsh-mcp-client` 的 `apply(ctx, config)` 在 `packages/mcp/mcp-client/src/index.ts:140-181` 已经做完了：

```ts
// mcp-client 内部（你看 packages/mcp/mcp-client/src/connection.ts 知道细节）
const connection = startConnection(ctx, config, reconnect)   // 启动连接
await connection.ready                                       // 等工具发现完
// ↑ 内部已经做了 ctx.tools.register('mcp__<serverName>__<raw>', ...)
//   你完全不需要写这一行
```

**你只要**：往 plugin 树里塞一个 `name: '@deepseek-ai/dsh-mcp-client'` 的 row，配好 config。

### 2.2 不需要写"触发 HMR"代码

dsh 的 `app-boot` / `cordis-plugin-loader` 监听了 `~/.dsh/profiles/<name>/cordis.patch.yml` 的 mtime 变化。**你写完 patch 文件，下次 dsh 启动 / HMR 触发时自动加载**。

### 2.3 不需要维护"工具名列表"

工具名由 mcp server 在握手时返回，dsh-mcp-client 实时拿到并注册。你**永远不需要**预先知道有哪些 tool；MCP 协议的设计就是 server 端动态。

## 6. 阶段 2-4 的关键设计决策

### 6.1 谁来加载 mcp-client 实例？

**两种实现路径**：

| 路径 | 说明 | 状态 |
|------|------|------|
| **A. patch.yml 静态加载** | 用户填完表单 → 写 patch.yml → dsh Loader 解析时启动 mcp-client 实例 | ✅ **推荐**。跟 dsh 现有插件模式一致，HMR 自动处理 |
| **B. 运行时动态 plugin(ctx, McpClientInstance, cfg) 程序化加载** | UI 提交后，Host 服务**直接 `ctx.plugin(McpClientInstance, cfg)`** 在运行时加载实例 | ❌ **不推荐**。会绕开 Loader 的命名空间 / 生命周期管理，xml/yaml expression 没法持久化 |

**方案 A 路径**（你最终要做的）：

```yaml
# 用户保存表单后写出的 patch.yml
- insert:
    - id: mcp-memory
      name: '@deepseek-ai/dsh-mcp-client'   # ← 这关键：loader 看到 name 找到 dsh-mcp-client 包
      config:
        serverName: memory
        transport: stdio
        command: memorix
        args: [serve]
        env: {}
        cwd: ''
        toolCallTimeoutMs: 60000
        failOnStartupError: false
```

Loader 解析 → `require('@deepseek-ai/dsh-mcp-client')` → 找到 `name`='mcp-client' 的 plugin → 调 `apply(ctx, config)` → 内部启动子进程 → 工具发现 → 注册完成。

**这一步完全不需要你写代码**。你只要保证 patch 文件写对了。

### 6.2 row 的 id 怎么定？

**推荐**：`mcp-${serverName}`（见 `1.md`、原 `2.md`）。

```yaml
- id: mcp-memory       # ← serverName=memory → id 固定为 mcp-memory
  name: '@deepseek-ai/dsh-mcp-client'
  config: { serverName: memory, ... }
```

**为什么 id 要稳定**：
- HMR 时 loader 比较新旧行（id 相同就 dispose 旧实例 + 创建新实例；id 不同就累加）
- 改 id = 旧实例不卸载、新实例叠加 = 工具注册两份（要么 serverName 冲突抛错，要么注册两个同名工具污染 ctx）
- 你 UI 也按 `mcp-${serverName}` 当 row 主键，删 / 改都用它

### 6.3 多 profile 怎么办？

**简化方案（推荐 MVP）**：

写 patch 文件时**只写 home-level**：`$DSH_HOME/cordis.patch.yml`（不写 `profiles/<name>/` 下）。这样所有 profile 共享一份 MCP 配置。

**进阶方案**：

从 `process.env.DSH_PROFILE` 或 `argv` 提取 profile 名，写到 `profiles/<name>/cordis.patch.yml`。每个 profile 独立。

`PatchStore` 暴露一个 `targetLayer: 'home' | 'profile'` 配置。

### 6.4 写 patch 时保留用户原有内容

直接 `yaml.dump()` 会破坏两件事：

1. 用户自己加的 `!!js` 表达式（host feature，写 Node.js 代码注入到 config）
2. 用户手工加的其它 row（不是我插件的）

**必须**用 `@deepseek-ai/cordis-plugin-include` 的 `applyEntryPatches(base, layers)` 重新合成：

```ts
import Include, { applyEntryPatches, entryListSchema } from '@deepseek-ai/cordis-plugin-include'
import * as yaml from 'js-yaml'

// 读
const layers = yaml.load(fs.readFileSync(path, 'utf8'), { schema: entryListSchema }) as any[]
// 改（只过滤掉 mcp-client 同 serverName 的旧行）
for (const layer of layers) {
  if (layer.insert) {
    layer.insert = layer.insert.filter(
      (r: any) => !(r.name === '@deepseek-ai/dsh-mcp-client' && r.config?.serverName === config.serverName),
    )
  }
}
if (!layers[0]) layers[0] = { insert: [] }
layers[0].insert.push({ id: `mcp-${config.serverName}`, name: '@deepseek-ai/dsh-mcp-client', config })
// 写
const composed = applyEntryPatches([], layers)   // 重新合成
const tmp = `${path}.tmp`
fs.writeFileSync(tmp, yaml.dump(composed, { schema: entryListSchema, noRefs: true }), 'utf8')
fs.renameSync(tmp, path)   // 原子写
```

参考实现：`packages/boot/app-boot/src/profile.ts:413-420` `composeEntries`。

### 6.5 工具注册不需要你写 —— 但你要观测到

**观测手段**：

```ts
// Host 端 list() 增强：把 loader fiberPhase 叠加
const entries = patchStore.list()   // 纯 patch 数据
const loaderEntries = ctx.loader.entries().filter(e => e.options.name === '@deepseek-ai/dsh-mcp-client')
const byServerName = new Map(loaderEntries.map(e => [e.options.config?.serverName, e]))

// 合并：UI 看到 entry 时携带 status
const uiEntries = entries.map(e => ({
  ...e,
  status: byServerName.get(e.serverName)?.fiber?.state ?? 'pending',
}))
```

但 `loaderEntries` 里 `options.config.serverName` 不一定回填（patch 行若 config 字段没被 loader 解析回来）。**兜底**：list() 里直接按 *config 字段*匹配。

## 7. 阶段 5（可选）：让 UI 看到工具注册状态

### 7.1 想看到什么

| 用户 期望 | 底层数据 |
|----------|---------|
| "memory server 的 save 工具已注册" | `ctx.tools.get('mcp__memory__save')` 不为 null |
| "这个 server 连接失败" | fiber state = `failed` |
| "正在连接" | fiber state = `pending` 或 `loading` |
| "工具已就绪但 dsh 总线没收到" | 不可能，激活后会推送 |

**最直接的查询**：**遍历 `ctx.tools`**，列出所有 `mcp__` 开头的工具名。

```ts
// Host 端
@Remote('listTools') allTools(): { name: string; serverName: string }[] {
  const out: { name: string; serverName: string }[] = []
  for (const toolName of ctx.tools.keys()) {
    if (toolName.startsWith('mcp__')) {
      const parts = toolName.split('__')
      if (parts.length >= 3) {
        const serverName = parts[1]
        const rawName = parts.slice(2).join('__')
        out.push({ name: rawName, serverName })
      }
    }
  }
  return out
}
```

**`ctx.tools.keys()`** 是否提供要看 `dsh-tools` 的 API —— 实际看 `packages/tools/tools/src/index.ts`，一般都有 `iter()` / `list()`。

### 7.2 UI 怎么呈现

两个思路：

**A. 状态徽标**：每个 serverName 行右侧显示 `active / failed / loading`
- 数据源：`ctx.loader.entries()`
- 阶段 5 做，**简单**

**B. 工具列表展开**：点 serverName 行展开下面所有 tool
- 数据源：`ctx.tools` 迭代
- 阶段 5+，**更强**

**MVP 不做 5**，等你阶段 1-4 跑通再补。

## 8. 重要的"不要做"清单（避免返工）

| ❌ 不要做 | 为什么 |
|----------|--------|
| 在 `apply(ctx)` 里**手动** `ctx.tools.register('mcp__xxx__yyy', ...)` | dsh-mcp-client 已经做了。你注册一份会冲突。 |
| 自己**实现** MCP 协议（stdio、HTTPSSE、JSON-RPC） | dsh-mcp-client 全做了。 |
| 用 `webServer.route('POST', '/api/mcp/save', ...)` | dsh 不用 webServer.route，是 `TypertRemoteService` 模式。 |
| 用 `yaml.dump()` 裸写 patch | 会破坏 `!!js` 表达式和用户其他 row。**必须** `applyEntryPatches` 重合成。 |
| 用 `cordis.patch.yml` 写 `defaults` 字段塞 mcp-client config | 用户配置应该**只写到用户的 patch 文件**（`~/.dsh/profiles/<name>/cordis.patch.yml`），不能写你自己 bundle 的 `cordis.patch.yml` 里。 |
| 试图"对接外部 mcp 注册对应工具" | mcp-client 实例启动时已经注册。**你只配置 client 实例**。 |
| 写 `src/invariant.ts` / `src/client/invariant.ts` | 仓库内 monorepo 制度，外部 bundle 不写。 |
| `apply()` 里直接修改 `cordis.patch.yml` | 你的 bundle 加载顺序在用户 patch 之后。**只能让用户自己 patch 文件写好**。 |
| 试图在 `apply()` 里 `ctx.plugin(McpClientInstance, cfg)` 程序化加载 | 绕开 Loader 生命周期管理，xml/$js 不被持久化。**只能走 patch 文件**。 |

| `src/index.ts` 提供 HTTP API | `src/gateway.ts` 提供 Remote API | ✅ 沿用 2.md |
| `src/client/index.ts` 用 `children: { 'settings.mcp.item': ... }` | `children` 字段是 owner 用的，registrant 不写 | ✅ 沿用 2.md 修正 |
| 列了一个 `host:` 路径下新建包 | 一个 bundle 包内含 host + client 两面 | ✅ 沿用 2.md |

**结论**：本方案 ≡ `2.md` 工程化实现，**不引入 `1.md` 的 webServer.route 路径**。

## 11. 未来扩展（"每次对话可选 tool"）

> 你提到的"后续实现每次对话可选 tool"，这个**不在 MVP 范围**。但这里给一段预热：

### 11.1 agent loop 当前是怎么选 tool 的？

dsh 的 agent loop 内部维护一个 tool 列表（所有 `ctx.tools` 注册的工具）。**每轮对话**，模型拿到工具列表，**自主决定**调哪些、调几个、参数是什么。

**所以"每轮对话可选 tool"，目前就是默认行为**：每轮都把所有 `mcp__xxx__yyy` 工具给模型。

### 11.2 想要"按对话限定工具"该怎么做？

如果你想做"这次对话只能用 memory 工具，不能用 github 工具"，有两条路：

| 路径 | 说明 | 复杂度 |
|------|------|--------|
| **A. 工具列表过滤** | 在 agent loop 的工具选择前加一层过滤（黑/白名单），只在选 tool 时筛**模型看到**的列表 | 中等。要在 agent loop 包里改 |
| **B. 启停 mcp-client 实例** | 某个对话开始时 `ctx.plugin(McpClientInstance, cfgInstagram)`，结束时 `dispose`。最重 | 重。还要考虑 dispose 副作用 |
| **C. 工具 schema 标记 enabled** | 给 `ctx.tools.register` 加 `enabled: boolean` 字段，agent loop 读它 | 轻。看仓库是否支持 |

**MVP 别碰**。先把阶段 1-5 跑通。
