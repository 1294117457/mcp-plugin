# MCP 外部插件方案

> 本文面向**不太熟悉 dsh 仓库**的开发者：读完应该知道要建哪些文件、要装哪些依赖、各文件分别写什么。
>
> 工作目录：`my-dsh-plugin/mcp/`。对 deepseek-harness 仓库**零修改**。

---

## 0. 先建心智模型（30 秒）

dsh 装一个 **"插件（plugin）"** = 一个 npm 包，包里有一个 `apply(ctx)` 函数。dsh 启动时会按 profile 列表加载这些包，调用它们的 `apply()`，把上下文（`ctx`）交给你。

你要做的 MCP 插件，本质上是：

```
加载时  → 把 "@deepseek-ai/dsh-mcp-client" 这个仓库自带的 MCP 客户端
         装一份进 ctx（按 serverName 一份）。
         这一步通过写 cordis.patch.yml 实现。

渲染时  → 在 dsh 设置弹窗里多一个 "MCP 服务" 标签页，
         用户能看 / 增 / 删 / 改这些 server 配置。
         这一步通过注册一个 settings.section slot 实现。
```

要碰到的活儿分两类：

| 场景 | 跑在哪 | 你要写的代码 |
|------|--------|--------------|
| dsh 启动时（Node.js 进程里） | Host | `src/*.ts` |
| 用户开浏览器时（React 树里） | Browser（Client） | `src/client/*.tsx` |

**两份代码共享同一个 npm 包**（一个 package.json），靠 `package.json` 的两个 entry 字段分开加载。

## 2. 要装哪些依赖（按必要性排）

下面这张表告诉你 **装哪个、装在哪个 package.json 字段、为什么**。完整代码示例在 §3 后开始讲。

| npm 包 | 装在哪 | 它帮你做的事 |
|--------|--------|--------------|
| `@deepseek-ai/dsh-mcp-client` | dependencies | **唯一必须装的运行时包**。帮你跑 MCP 协议（stdio 子进程 + Streamable-HTTP），工具发现、重连、命名空间校验都内置。你只是装它、配它。 |
| `@deepseek-ai/cordis` | dependencies | dsh 用的 IoC 容器。你要 `import type { Context } from '@deepseek-ai/cordis'` 来标 `apply(ctx)` 签名。 |
| `@deepseek-ai/dsh-mcp-client` (同时) | 见 §3.1 | 它的 `Config` 是 schema，把"server 的 config 长什么样"的所有字段定下来。**直接复用，不要自己造**。 |
| `@deepseek-ai/dsh-typert-protocol` | dependencies | `TypertRemoteService` 基类 + `@Remote(...)` 装饰器。你写一个类继承它，Browser 端就自动出现 `ctx.remote.mcpSettings.xxx()`。 |
| `@deepseek-ai/cordis-plugin-include` | dependencies | 解析 `cordis.patch.yml` 的库，并提供 `applyEntryPatches(base, layers)` 和 yaml schema（含 `!!js` 表达式节点）。写 patch 时**必须用它**，普通 `yaml.dump()` 会破坏其它用户配置。 |
| `@deepseek-ai/dsh-home-paths` | dependencies | `dshHomePath('profiles', name, 'cordis.patch.yml')` —— 拼出要写哪个文件。 |
| `@deepseek-ai/dsh-client-ui-slots` | client dependencies | 提供 `ctx.slots.inject / register` API 和 props 类型（`PropsRuntime`、`PropsRenderSlots`、`PropsStore`、`inject`）。写 Client `index.ts` 必须用。 |
| `@deepseek-ai/dsh-client-ui-settings` | client type-only | 仅做 `import type {} from '@deepseek-ai/dsh-client-ui-settings/client'`，是为了让 TS 知道 `'settings.section'` 这条 slot 类型存在。**运行时并不需要这个包**。 |
| `@deepseek-ai/dsh-client-locale` | client type-only | 仅 `import type {} from '@deepseek-ai/dsh-client-locale/client'`，让 `ctx.locale.register()` 有类型。 |
| `@deepseek-ai/dsh-client-connection` | client type-only | 给你 `ctx.get('connection')` 和 `ConnectionHandle['api']` 的类型（手柄**由 dsh 在 Client 启动时塞进去**，你只是用）。 |
| `@deepseek-ai/dsh-client-web-react` | client type-only | `defineStore({...})` factory —— 把状态接上 React 的 `useSyncExternalStore`。 |
| `@deepseek-ai/dsh-api-remotes` | client type-only | `ctx.remote.xxx.yyy()` 的类型：来自 Host 端 TypertRemoteService 的远端方法。 |
| `@deepseek-ai/schemastery` | optional | dsh 用的 zod 风格 schema 库。要在 Host 端自己 export 副本时用，否则不必。 |

> **type-only 依赖**装在 `package.json` 里是 `import type {} from '.../client'` 的 `{}` —— 让 TS 看到该包的客户端 ctx 扩展，但运行时不会加载该包代码。`dsh-home-paths`、`cordis-plugin-include` 这些你真要 `import` 函数用，**别**这么写，要真装。

把上面那些 `type` 型依赖折成 versions 引用方式（举一例）：

```ts
import type {} from '@deepseek-ai/dsh-client-ui-settings/client'   // 拼 ctx 类型
import type {} from '@deepseek-ai/dsh-client-locale/client'        // 拼 ctx 类型
import type {} from '@deepseek-ai/dsh-client-connection/client'    // 拼 ctx 类型
import type {} from '@deepseek-ai/dsh-client-ui-slots/client'      // 拼 ctx 类型
```

可以放在 `src/client/index.ts` 顶部一次性 import。

## 3. Host 端：要写的 5 个文件

Host 端的工作：**把 patch 文件读出来给 Browser、看，把 Browser 提交的 config 写回 patch**。

### 3.1 `src/types.ts` — 先写，配置一目了然

**为什么**：所有 Host / Client 都要共享 "server 长什么样" 的形状。先在这里定义，避免在 gateway 和 client store 各写一遍。

**写什么**：

```ts
import type { Config } from '@deepseek-ai/dsh-mcp-client'

// McpServerConfig 就是 dsh-mcp-client 的 Config；起个本地别名方便读
export type McpServerConfig = Config

// 列表里的一行（给 UI 看的）
export interface McpListEntry {
  serverName: string
  transport: 'stdio' | 'streamable-http'
  command?: string        // stdio 时填
  args?: string[]         // stdio 时填
  url?: string            // http 时填
  headers?: Record<string, string>  // http 时填
  status?: 'pending' | 'loading' | 'active' | 'failed' | 'disabled' | null
}

// Remote API 统一返回类型
export type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: { code: string; message: string } }
```

**踩坑**：`serverName` 必须满足 `/^[A-Za-z0-9_-]{1,32}$/`，写哪儿都拦一道。

### 3.3 `src/patch-store.ts` — patch 文件读写工具（核心）

**为什么**：你的 Remote API（list / add / remove）最终都要落到 `$DSH_HOME/profiles/<name>/cordis.patch.yml` 这个文件上。直接 `yaml.dump()` 会破坏其它用户的 `!!js` 表达式，必须走 `@deepseek-ai/cordis-plugin-include` 的 `applyEntryPatches` 合成算法。

**写什么**：

```ts
import * as fs from 'node:fs'
import * as path from 'node:path'
import Include, { applyEntryPatches, entryListSchema } from '@deepseek-ai/cordis-plugin-include'
import { dshHomePath } from '@deepseek-ai/dsh-home-paths'
import type { Config } from '@deepseek-ai/dsh-mcp-client'
import type { McpListEntry, Result } from './types.ts'

const ROW_NAME = '@deepseek-ai/dsh-mcp-client'

function patchPath(profileName: string | null): string {
  // 简化版：先写到一个 profile；profile 名未知就写到 home-level layer
  return profileName
    ? dshHomePath('profiles', profileName, 'cordis.patch.yml')
    : dshHomePath('cordis.patch.yml')
}

function loadPatch(p: string) {
  const txt = fs.readFileSync(p, 'utf8')
  return yaml.load(txt, { schema: entryListSchema }) as any[]
}

function writePatch(p: string, layers: any[]) {
  const composed = applyEntryPatches([], layers)
  const yamlText = yaml.dump(composed, { schema: entryListSchema, noRefs: true })
  // 临时文件再 rename，原子写
  const tmp = `${p}.tmp`
  fs.writeFileSync(tmp, yamlText, 'utf8')
  fs.renameSync(tmp, p)
}

export function createPatchStore(profileName: string | null) {
  const file = patchPath(profileName)

  return {
    list(): McpListEntry[] {
      if (!fs.existsSync(file)) return []
      const layers = loadPatch(file)
      const out: McpListEntry[] = []
      for (const layer of layers) {
        for (const row of layer.insert ?? []) {
          if (row.name === ROW_NAME) {
            out.push({ ...row.config, serverName: row.config.serverName })
          }
        }
      }
      return out
    },

    add(config: Config): Result<true> {
      try {
        const layers = fs.existsSync(file) ? loadPatch(file) : []
        // 删掉同 serverName 的旧行（按 row.name 筛所有 mcp-client 行）
        for (const layer of layers) {
          if (layer.insert) {
            layer.insert = layer.insert.filter(
              (r: any) => !(r.name === ROW_NAME && r.config?.serverName === config.serverName),
            )
          }
        }
        // 准备新行
        const newRow = { id: `mcp-${config.serverName}`, name: ROW_NAME, config }
        // 加到第一层 insert
        if (!layers[0]) layers[0] = { insert: [] }
        layers[0].insert = [...(layers[0].insert ?? []), newRow]
        writePatch(file, layers)
        return { ok: true, value: true }
      } catch (e: any) {
        return { ok: false, error: { code: 'PATCH_WRITE', message: String(e) } }
      }
    },

    remove(serverName: string): Result<true> {
      try {
        if (!fs.existsSync(file)) return { ok: true, value: true }
        const layers = loadPatch(file)
        for (const layer of layers) {
          if (layer.insert) {
            layer.insert = layer.insert.filter(
              (r: any) => !(r.name === ROW_NAME && r.config?.serverName === serverName),
            )
          }
        }
        writePatch(file, layers)
        return { ok: true, value: true }
      } catch (e: any) {
        return { ok: false, error: { code: 'PATCH_WRITE', message: String(e) } }
      }
    },
  }
}

export type PatchStore = ReturnType<typeof createPatchStore>
```

**踩坑**：
- 不要 `yaml.dump()` 裸写：会丢 `!!js` 表达式和用户其他 row。**必须** `applyEntryPatches` 重新合成。
- 筛选时按 `row.name === '@deepseek-ai/dsh-mcp-client'`，不按 `row.id`：用户可能改 `id`，但所有实例都共享这个 `name`。
- 写失败要回滚：先写 tmp 文件再 `rename`。
- profile 名从哪儿拿？要么从 `DSH_PROFILE` 环境变量，要么从 `process.argv` 提取，要么 **简化** —— 直接写到 home-level layer（对所有 profile 生效），MVP 推荐这种。

### 3.4 `src/gateway.ts` — 把 patch-store 的方法暴露到 Browser

**为什么**：Client 里只能调 Browser ctx 上的方法，不能直接访问 Host 的 `fs` / Node API。要通过 `@Remote(...)` 装饰器把 patch-store 的 3 个方法标记成"远端可调"。

**写什么**：

```ts
import type { Context } from '@deepseek-ai/cordis'
import { TypertRemoteService, Remote } from '@deepseek-ai/dsh-typert-protocol'
import type { Config } from '@deepseek-ai/dsh-mcp-client'
import type { McpListEntry, Result } from './types.ts'
import type { PatchStore } from './patch-store.ts'

export class McpSettingsGateway extends TypertRemoteService {
  constructor(ctx: Context, private readonly store: PatchStore) {
    super(ctx, 'mcpSettings')   // 浏览器端看到 ctx.remote.mcpSettings.xxx
  }

  @Remote('list') list(): McpListEntry[] {
    return this.store.list()
  }

  @Remote('add') add(config: Config): Result<true> {
    return this.store.add(config)
  }

  @Remote('remove') remove(serverName: string): Result<true> {
    return this.store.remove(serverName)
  }
}
```

**踩坑**：
- `super(ctx, 'mcpSettings')` 第二个参数是 **service name**，要稳定、不要带空格、不要跟已有服务冲突。
- 返回值要可序列化：plain object，不能含 `Error` 实例。

### 3.5 `src/index.ts` — Host 入口

**写什么**：

```ts
import type { Context } from '@deepseek-ai/cordis'
import { McpSettingsGateway } from './gateway.ts'
import { createPatchStore } from './patch-store.ts'

export const name = 'my-dsh-mcp-settings'
export const inject = ['loader'] as const   // 等 loader 起来再注册

export function apply(ctx: Context): void {
  // 简化：先读环境变量；没有就写到 home-level layer
  const profileName = process.env.DSH_PROFILE ?? null
  const store = createPatchStore(profileName)
  ctx.plugin(McpSettingsGateway, { store })
}
```

`name`、`inject`、`apply(ctx)` 是 cordis 标准的 plugin 三个 export。dsh 启动时会按 name 顺序、确保 inject 服务可用后再调 apply。

> 你可能看到 dsh 仓库里插件用 `export const apply = (ctx) => ...`，跟 `export function apply` 等价。用 `function` 更易读。

### 4.2 `src/client/mcp-store.ts` — Client 状态

**为什么**：组件用 store 渲染；store 调 Remote API。**禁止**让组件直接 import `@deepseek-ai/dsh-client-connection`，所有 ctx 服务通过 apply 闭包注入。

**写什么**：

```ts
import { defineStore } from '@deepseek-ai/dsh-client-web-react'
import type { Config } from '@deepseek-ai/dsh-mcp-client'
import type { McpListEntry, Result } from '../types.ts'

// api 是 ConnectionHandle['api'] 类型；只知道有 mcpSettings.{list,add,remove}
type Remote = {
  mcpSettings: {
    list: () => Promise<Result<McpListEntry[]>>
    add: (config: Config) => Promise<Result<true>>
    remove: (serverName: string) => Promise<Result<true>>
  }
}

interface State {
  entries: McpListEntry[]
  status: 'idle' | 'loading' | 'error'
  error: string | null
  editing: McpListEntry | null  // 正在编辑的行（null 表示新增模式）
}

export function createMcpStore(api: Remote) {
  const store = defineStore<State>({
    entries: [],
    status: 'idle',
    error: null,
    editing: null,
  })

  return {
    ...store,           // 包含 subscribe / snapshot / useSnapshot 等
    load: async () => {
      store.update(s => ({ ...s, status: 'loading', error: null }))
      const r = await api.mcpSettings.list()
      if (r.ok) store.update(s => ({ ...s, entries: r.value, status: 'idle' }))
      else store.update(s => ({ ...s, status: 'error', error: r.error.message }))
    },
    startAdd: () => store.update(s => ({ ...s, editing: null })),   // null = 新增
    startEdit: (entry: McpListEntry) => store.update(s => ({ ...s, editing: entry })),
    cancelEdit: () => store.update(s => ({ ...s, editing: null })),
    save: async (cfg: Config) => {
      const r = await api.mcpSettings.add(cfg)
      if (r.ok) await store.load()
      else store.update(s => ({ ...s, error: r.error.message }))
    },
    remove: async (serverName: string) => {
      const r = await api.mcpSettings.remove(serverName)
      if (r.ok) await store.load()
      else store.update(s => ({ ...s, error: r.error.message }))
    },
  }
}

export type McpStore = ReturnType<typeof createMcpStore>
```

**踩坑**：
- store 用 `defineStore({...})` factory，**禁止模块级 handle**（不能在模块顶层 `new`，要在 `apply` 里 new 一次）。
- `save / remove` 后调 `load()` 回拉一次，简化 HMR 失效场景。

### 4.3 `src/client/McpSection.tsx` — Tab 根组件

**写什么**：

```tsx
import css from './McpSection.module.css'
import { McpRow } from './McpRow.tsx'
import { McpForm } from './McpForm.tsx'
import type { PropsRuntime, PropsRenderSlots } from '@deepseek-ai/dsh-client-ui-slots'
import type { McpStore } from './mcp-store.ts'

export interface McpSectionInjected {
  store: McpStore
  t: (key: string) => string
}

export type McpSectionProps =
  PropsRuntime<'settings.section'>   // 平台注入的 useSnapshot / dispatch 等
  & PropsRenderSlots<never>
  & McpSectionInjected

export function McpSection({ useSnapshot, store, t }: McpSectionProps) {
  const state = useSnapshot(s => s)   // 等价于 store.useSnapshot，但 props 注入

  return (
    <div className={css.section}>
      <header className={css.header}>
        <h2>{t('nav.title')}</h2>
        <button onClick={() => { store.startAdd(); /* 触发新增表单 */ }}>
          {t('row.add')}
        </button>
      </header>

      <ul className={css.list}>
        {state.entries.map(e => (
          <McpRow
            key={e.serverName}
            entry={e}
            t={t}
            onEdit={() => store.startEdit(e)}
            onDelete={() => store.remove(e.serverName)}
          />
        ))}
      </ul>

      {state.editing !== null || true /* 简化：始终展示表单，新增 / 编辑都用同一个 */ ? (
        <McpForm
          store={store}
          t={t}
          initial={state.editing ?? undefined}
          onCancel={() => store.cancelEdit()}
        />
      ) : null}

      {state.error ? <div className={css.error}>{state.error}</div> : null}
      <div className={css.notice}>{t('notice.webRestart')}</div>
    </div>
  )
}
```

**踩坑**：
- 不要在组件里 `import { ctx } from ...`——业务组件不直接 import `ctx`。`useSnapshot`、`t`、`store` 都通过 props 进来（由 apply 闭包注入，见 §4.7）。
- `useSnapshot` 是 `props.useSnapshot`，**不是** import 的 symbol。

### 4.4 `src/client/McpRow.tsx` — 列表一行

**写什么**：

```tsx
import css from './McpSection.module.css'
import type { McpListEntry } from '../types.ts'

interface Props {
  entry: McpListEntry
  t: (key: string) => string
  onEdit: () => void
  onDelete: () => void
}

export function McpRow({ entry, t, onEdit, onDelete }: Props) {
  const detail = entry.transport === 'stdio'
    ? `${entry.command ?? ''} ${(entry.args ?? []).join(' ')}`
    : entry.url ?? ''
  return (
    <li className={css.row}>
      <span className={css.name}>{entry.serverName}</span>

```

### 4.5 `src/client/McpForm.tsx` — 添加 / 编辑表单

**写什么**（简化版骨架）：

```tsx
import { useState } from 'react'
import css from './McpSection.module.css'
import type { Config } from '@deepseek-ai/dsh-mcp-client'
import type { McpListEntry } from '../types.ts'
import type { McpStore } from './mcp-store.ts'

interface Props {
  store: McpStore
  t: (key: string) => string
  initial?: McpListEntry
  onCancel: () => void
}

const STORAGE_RE = /^[A-Za-z0-9_-]{1,32}$/

export function McpForm({ store, t, initial, onCancel }: Props) {
  const [serverName, setServerName] = useState(initial?.serverName ?? '')
  const [transport, setTransport] = useState<'stdio' | 'streamable-http'>(
    initial?.transport ?? 'stdio',
  )
  const [command, setCommand] = useState(initial?.command ?? '')
  const [url, setUrl] = useState(initial?.url ?? '')
  // ... args / env / headers 等字段同理

  async function onSubmit(e: React.FormEvent) {
    e.preventDefault()
    if (!STORAGE_RE.test(serverName)) {
      alert(t('error.serverName'))
      return
    }
    const cfg: Config = transport === 'stdio'
      ? { serverName, transport, command, args: [] }
      : { serverName, transport, url }
    await store.save(cfg)
    onCancel()
  }

  return (
    <form onSubmit={onSubmit} className={css.form}>
      <label>{t('field.serverName')}<input value={serverName} onChange={e => setServerName(e.target.value)} disabled={!!initial} /></label>
      <label>{t('field.transport')}
        <select value={transport} onChange={e => setTransport(e.target.value as any)}>
          <option value="stdio">stdio</option>
          <option value="streamable-http">streamable-http</option>
        </select>
      </label>
      {transport === 'stdio' ? (
        <label>{t('field.command')}<input value={command} onChange={e => setCommand(e.target.value)} /></label>
      ) : (
        <label>{t('field.url')}<input value={url} onChange={e => setUrl(e.target.value)} /></label>
      )}
      <button type="submit">{t('row.save')}</button>
      <button type="button" onClick={onCancel}>{t('row.cancel')}</button>
    </form>
  )
}
```

**踩坑**：
- **serverName 编辑不建议开** —— 它锁住了 row 的 id 和工具名前缀，改名等于删除重建。MVP 直接 `disabled={!!initial}`。
- transport 切换要清空多余字段，避免提交出去的 Config schema 校验失败（最后用 `McpClientConfigSchema` 兜一道）。

### 4.7 `src/client/index.ts` — Client 入口（注册 slot）

**为什么**：所有 §4 文件需要在这里"组装起来"——拿 connection handle、new 一个 store、把 store / t 注入给 McpSection、把 McpSection 注册到 settings.section slot。

**写什么**：

```tsx
// 类型拼装（运行时 zero-cost；让 TS 知道这些 ctx 服务存在）
import type {} from '@deepseek-ai/dsh-client-ui-settings/client'
import type {} from '@deepseek-ai/dsh-client-locale/client'
import type {} from '@deepseek-ai/dsh-client-connection/client'
import type {} from '@deepseek-ai/dsh-client-ui-slots/client'

import type { Context } from '@deepseek-ai/cordis'
import { McpSection, type McpSectionInjected } from './McpSection.tsx'
import { createMcpStore } from './mcp-store.ts'
import { zh, en } from './locales.ts'

export const name = 'my-dsh-mcp-settings:client'
export const inject = ['connection', 'locale', 'slots'] as const

export function apply(ctx: Context): void {
  const NS = 'settings.mcp'
  ctx.effect(() => ctx.locale.register(NS, { zh, en }), 'mcp-settings: dictionaries')
  const t = ctx.locale.bind(NS)

  // ctx.get 是类型擦除的；事实上这里拿到的是 ConnectionHandle
  const connection = ctx.get('connection') as unknown as {
    api: { mcpSettings: {
      list: () => Promise<any>
      add: (cfg: any) => Promise<any>
      remove: (sn: string) => Promise<any>
    } }
  }

  const store = createMcpStore(connection.api)

  // 顺手预热：拉一次
  ctx.effect(() => { void store.load() }, 'mcp-settings: initial-load')

  // 通过 inject props 把 store / t 传给 McpSection
  const injectedProps: McpSectionInjected = { store, t }

  ctx.slots.inject('settings.section', () =>
    ctx.slots.register(
      {
        name: 'settings.section',
        id: 'mcp',
        order: 20,
        label: () => t('nav.title'),
        locale: NS,
        inject: injectedProps,
      },
      McpSection,
    ),
  )
}
```

**踩坑**：
- **`ctx.slots.inject('settings.section', ...)` 必须两层**：外层 `inject` 等目标 slot 被其它 owner 声明（这里是 `ui-settings-general`），里层 `register` 才执行。如果你漏外层、目标 slot 还没声明会抛错。
- 不要在 register options 里写 `children`：那是 owner 用来声明子 slot 的。
- store 一定要在 `apply` 里 `new`，**禁止**模块级单例。

## 10. 已知坑（按出现频率）

1. **slot 必须 `inject` 包裹 `register`**：漏外层 `ctx.slots.inject('settings.section', ...)` 会抛 "未声明 slot" 错。
2. **写 patch 不能 `yaml.dump` 裸写**：用户 patch 文件里的 `!!js` 表达式和其它 row 都会被破坏，必须 `applyEntryPatches` 重合成。
3. **store 不能模块级 new**：必须 `apply` 闭包内 new；模块级 handle 在所有 ctx 都看到同一份，导致 HMR / 多 profile 串。
4. **CSS 别硬编码颜色**：仓库有浅 / 深主题，颜色走 `--dsw-*` token。
5. **web profile 下提交后需重启 dsh**：headless profile 有 HMR，web 没有（MVP 用 "请重启 dsh" 提示规避）。
6. **serverName 不能改**：它在 row `id` 里、又作为工具名前缀。改名等于删重建。表单 edit 模式把 serverName 字段 disabled。
7. **业务组件不直接 import `ctx`**：ctx 只在 `apply` 闭包内可见；组件通过 props 接 store / t / useSnapshot。
8. **Remote 调用返回值是 `{ ok, value }` 或 `{ ok:false, error }` 形态**：不要 `try/catch`，按 `r.ok` 分支。
