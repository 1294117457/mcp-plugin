# tohelper 当前实现总结

> 版本：0.5.0
>
> 更新时间：2026-09-01

## 1. 项目定位

tohelper 是一个 DSH (DeepSeek Harness) 插件，提供三层能力：

- **工具管理**：MCP Server 连接、内置工具浏览、工具屏蔽。
- **Task（任务单元）**：将 LLM + 工具 + Prompt 封装为可独立装配的 DSH Tool。
- **Node（多任务编排）**：通过 Pipeline 或 Loop 模式编排多个 Task。

插件以 Cordis 插件形式运行，Host 端注入 `webServer`、`tools`、`llm` 三个服务，Client 端通过 `slots` 注入 Web UI overlay。

## 3. 配置模型

### 3.1 统一配置文件 `data/config.json`

```ts
interface ConfigFile {
  version: 2
  tasks: Record<string, TaskConfig>
  nodes: Record<string, NodeConfig>
  equipped: string[]   // 已装配的 Task/Node ID 列表
}
```

Task 和 Node 使用带前缀的 ID（`task-xxx`、`node-xxx`），通过 `equipped` 数组统一管理装配状态。配置变更使用防抖写入（100ms debounce），先写临时文件再原子重命名。

### 3.2 MCP 配置文件 `data/tool-config.json`

```ts
interface ToolConfig {
  version: 1
  servers: Record<string, ServerEntry>
  denied: string[]     // 被屏蔽的工具名列表
}
```

MCP Server 配置独立于 Task/Node 配置，支持 `stdio` 和 `streamable-http` 两种传输方式。

## 4. Host 端实现

### 4.1 插件入口 (`host/index.ts`)

插件入口 `apply(ctx)` 执行以下初始化：

1. 创建 AgentTracker 追踪当前 Agent 实例。
2. 加载 `config.json`。
3. 初始化三个模块：Tool、Task、Node。
4. 注册 `/api/tohelper/config/reload` 端点，支持热重载配置。

### 4.2 Agent 追踪 (`agent-tracker.ts`)

AgentTracker 通过监听 `agent/created` 和 `agent/disposed` 事件追踪当前活跃的 Agent 实例。使用多种事件名变体（`/`、`-`、`.` 分隔）兼容不同版本 DSH。当事件机制不可用时，通过 `ctx.agents` 服务和 scope 链回退查找。

### 4.3 工具模块 (`tool/`)

功能：

- **MCP Server 管理**：连接/断开 MCP Server，自动发现工具，启动时自动重连标记为 `autoConnect` 的服务。
- **工具屏蔽**：通过 `agent.ctx.tools.restrict({ deny })` 限制特定工具对 Agent 的可见性。
- **工具列表**：返回分类的工具列表（内置/MCP），包含 inputSchema 和 outputSchema。
- **Skill 列表**：查询 `ctx.skills` 获取可用 Skill。
- **LLM 列表**：从多个来源聚合可用的 LLM 配置（provider 注册表、Agent 默认模型、config.json 中已配置的模型）。

API 端点：

| 路径 | 方法 | 说明 |
|---|---|---|
| `/api/tohelper/tools` | GET | 获取所有工具（分内置/MCP） |
| `/api/tohelper/skills` | GET | 获取 Skill 列表 |
| `/api/tohelper/llm/list` | GET | 获取可用 LLM 列表 |
| `/api/tohelper/mcp/servers` | GET | 获取已连接的 MCP Server 列表 |
| `/api/tohelper/mcp/add` | POST | 连接一个 MCP Server |
| `/api/tohelper/mcp/add-batch` | POST | 批量连接 MCP Server（JSON 配置） |
| `/api/tohelper/mcp/remove` | POST | 断开 MCP Server |
| `/api/tohelper/mcp/deny` | POST | 设置工具屏蔽列表 |
| `/api/tohelper/mcp/reset` | POST | 清空工具屏蔽列表 |
| `/api/tohelper/status` | GET | 获取插件状态 |

### 4.4 Task 模块 (`task/`)

**TaskConfig 定义**：

```ts
interface TaskConfig {
  id: string
  name: string           // 工具名，需符合 [a-z][a-z0-9_]{2,49}
  description: string    // 工具描述，影响 Agent 调用决策
  taskPrompt: string     // System Prompt，指导 LLM 行为
  llm: LLMSlot           // 指定 provider/model/temperature/maxTokens
  tools: string[]        // 允许调用的工具名列表
  inputSchema: object    // 输入 JSON Schema
  outputSchema: object   // 输出 JSON Schema
  createdAt: string
}
```

**Task 执行流程**（`task/executor.ts`）：

Task 使用 "提取参数 → 调用工具 → 汇总结果" 的三段式流程，避免依赖轻量模型不稳定的 function calling：

1. 如果 Task 没有配置工具，直接用 LLM 处理输入并返回。
2. 如果有工具，对每个工具：
   - 无必填参数：直接调用。
   - 有必填参数：先用 LLM 从 taskPrompt + 用户输入中提取参数 JSON，再调用工具。
3. 收集所有工具返回结果，用 LLM 按 taskPrompt 汇总为最终输出。

**装配机制**（`task/index.ts`）：

Task 装配后注册为 DSH Tool，优先注册到 Agent scope（`agent.ctx.tools.register`），失败时回退到全局 scope（`ctx.tools.register`）。当新 Agent 创建时（`agent/created` 事件），自动将所有已装配的 Task 重新注册到新 Agent scope。启动后 3 秒有一个 fallback 检查确保装配生效。

API 端点：

| 路径 | 方法 | 说明 |
|---|---|---|
| `/api/tohelper/task/list` | GET | 获取所有 Task |
| `/api/tohelper/task/create` | POST | 创建 Task |
| `/api/tohelper/task/update` | POST | 更新 Task |
| `/api/tohelper/task/delete` | POST | 删除 Task（被 Node 引用时拒绝） |
| `/api/tohelper/task/equip` | POST | 装配 Task 为工具 |
| `/api/tohelper/task/unequip` | POST | 卸载 Task |

### 4.5 Node 模块 (`node/`)

**NodeConfig 定义**：

```ts
interface NodeConfig {
  id: string
  name: string
  description: string
  mode: 'pipeline' | 'loop'
  nodePrompt: string     // Node 级 System Prompt
  llm: LLMSlot           // Node 级 LLM（用于汇总和 Loop 编排）
  tasks: string[]         // Task ID 列表（顺序即 Pipeline 执行顺序）
  inputSchema: object
  outputSchema: object
  triggerMode?: 'agent' | 'explicit' | 'both'
  failurePolicy?: 'fail_fast' | 'continue' | 'retry_then_continue'
}
```

**Pipeline 模式**（`node/executor.ts`）：

1. 按 `tasks` 数组顺序依次执行每个 Task。
2. 第一个 Task 接收用户原始输入，后续 Task 接收前一个 Task 的输出。
3. 根据 `failurePolicy` 决定失败时的行为：
   - `fail_fast`：标记后续 Task 为 skipped，立即返回。
   - `continue`：跳过失败 Task，继续执行后续 Task。
4. 所有 Task 完成后，用 Node LLM 汇总各 Task 结果生成最终输出。

**Loop 模式**（`node/executor.ts`）：

1. 为每个未完成的 Task 构建虚拟 Tool Schema（`task_<name>`）。
2. 每轮将用户输入和已完成结果作为上下文，调用 Node LLM 并传递虚拟工具。
3. LLM 通过 tool-call 选择要执行的 Task，执行后将结果加入上下文。
4. 当 LLM 不再发出 tool-call，或所有 Task 完成，或达到最大轮数（20），Loop 结束。
5. 汇总成功 Task 的结果生成最终输出。

**装配机制**：与 Task 相同，注册为 DSH Tool。

API 端点：

| 路径 | 方法 | 说明 |
|---|---|---|
| `/api/tohelper/node/list` | GET | 获取所有 Node |
| `/api/tohelper/node/create` | POST | 创建 Node |
| `/api/tohelper/node/update` | POST | 更新 Node |
| `/api/tohelper/node/delete` | POST | 删除 Node |
| `/api/tohelper/node/equip` | POST | 装配 Node 为工具 |
| `/api/tohelper/node/unequip` | POST | 卸载 Node |
| `/api/tohelper/node/run` | POST | 直接运行 Node（不经过 Agent） |
| `/api/tohelper/config/validate` | GET | 校验配置完整性 |
| `/api/tohelper/config/reload` | GET | 从磁盘热重载配置 |

### 4.6 执行结果协议

Task 和 Node 的执行结果使用结构化类型：

```ts
interface TaskResult {
  taskId: string
  taskName: string
  status: 'success' | 'failed' | 'timeout' | 'cancelled' | 'skipped'
  input?: unknown
  output?: unknown
  error?: ExecutionError
  attempt: number
  durationMs: number
  startedAt: string
  finishedAt: string
}

interface WorkflowResult {
  ok: boolean
  status: 'success' | 'partial_failure' | 'failed' | 'timeout' | 'cancelled'
  runId: string
  nodeId: string
  nodeName: string
  steps: TaskResult[]
  output?: unknown
  startedAt: string
  finishedAt: string
}
```

## 5. Client 端实现

### 5.1 入口和注入

Client 端是一个 React 应用，通过 DSH 的 `slots` 机制注入到 `shell.overlay` 层，以 Overlay 形式覆盖在 DSH Web 界面上方。CSS 通过运行时创建 `<style>` 标签注入。

### 5.2 交互入口：悬浮按钮 + 卫星菜单

- **FloatingButton**：固定在屏幕右下角的可拖拽圆形按钮（80x80px），支持 pointer capture 拖拽。单击（无位移）打开/关闭菜单。
- **SatelliteMenu**：围绕按钮中心均匀分布的 4 个菜单项：
  - **工具**：打开 ToolPanel。
  - **任务**：打开 TaskPanel。
  - **编排**：打开 NodePanel。
  - **刷新**：调用 `/api/tohelper/config/reload` 热重载配置。

### 5.3 ToolPanel（工具面板）

包含三个 Tab：

- **工具 Tab (ToolsTab)**：展示所有可用工具，按来源分组（内置/MCP/Task/Node），支持过滤。MCP 工具可以切换屏蔽状态，Task/Node 工具可以切换装配状态。每个工具可展开查看描述、inputSchema、outputSchema。
- **MCP Tab (McpTab)**：管理 MCP Server 连接。支持两种添加方式：表单模式（填写名称/URL/Headers）和 JSON 配置模式（粘贴 mcpServers JSON）。添加后先测试连接，成功后可保存或丢弃。
- **技能 Tab (SkillsTab)**：展示 DSH Skill 列表。

### 5.4 TaskPanel（任务面板）

左右分栏布局：

- **左栏**：Task 列表，显示名称、描述、LLM 配置和装配状态。
- **右栏**：Task 编辑器，包含名称、描述、taskPrompt（系统提示词）、LLM 选择、Temperature、工具多选。支持创建、保存、装配/卸载、删除操作。

### 5.5 NodePanel（编排面板）

画板式交互：

- **画板区 (NodeWorkspace)**：Node 以卡片形式展示在可缩放、可平移的画板上。每个卡片显示 Node 名称、模式（Pipeline/Loop）、关联的 Task 列表、LLM 模型。
- **Inspector 侧栏 (NodeInspector)**：选中 Node 后显示编辑面板，包含基本信息、Node Prompt、LLM/模式配置、Task 选择和排序。Pipeline 模式下 Task 支持上下箭头调整顺序。
- 支持创建新 Node、保存、装配/卸载、删除。

### 5.6 API 客户端

`client/api/` 封装了所有 Host 端 API 的调用：

- `toolApi`：工具、MCP、Skill、LLM 相关。
- `taskApi`：Task CRUD 和装配。
- `nodeApi`：Node CRUD 和装配。
- `configApi`：配置热重载。

## 6. 构建和部署

- **Host 端**：TypeScript 源码，运行在 Node.js 中，由 DSH 通过 `cordis.patch.yml` 直接加载 `src/host/index.ts`。
- **Client 端**：React + TypeScript，通过 Vite 构建为 `dist/client.js`，由 DSH Web 运行时加载。
- **安装**：`scripts/setup.js` 将插件注册到 DSH 的 cordis.yml 中，`scripts/unsetup.js` 反注册。

## 7. 已知限制

1. **模型兼容性**：部分轻量模型（如 glm-4-flash）的 function calling 不稳定，可能不调用工具或忽略描述不明确的工具。建议使用更强的模型或编写清晰的工具名和描述。
2. **配置同步**：直接编辑 `config.json` 文件后，需要通过"刷新"按钮或 `/api/tohelper/config/reload` 热重载才能生效。
3. **并发**：当前不支持同一 Node 的并发执行控制。
4. **持久化**：运行结果目前不持久化，后续计划迁移到 SQLite。

## 8. 后续规划

详见 `docs/2node/4优化/` 下的两份方案文档：

- **配置运行与固定工作流方案**：统一执行结果协议、确定性触发入口（命令/UI 按钮/API）、失败策略增强。
- **SQLite 与 Loop 动态编排方案**：配置和运行历史迁移到 SQLite、Loop 决策协议（run_task/finish）、完成条件/停滞检测/重试机制。
