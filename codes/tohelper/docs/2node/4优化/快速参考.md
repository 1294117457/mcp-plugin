# 配置统一与执行结果优化 - 快速参考

## 主要改进

### 1. 配置自动迁移 (v1 → v2)
- ✅ 首次启动自动检测并迁移 `node-config.json` → `config.json`
- ✅ Task 从 Node 内部提升到顶层，可被复用
- ✅ 自动创建带时间戳的备份文件
- ✅ 幂等迁移，重复执行安全

### 2. 结构化执行结果
```typescript
// 旧版本：只返回字符串
{ result: string }

// 新版本：完整的工作流结果
{
  ok: boolean
  status: 'success' | 'partial_failure' | 'failed' | 'timeout' | 'cancelled'
  runId: string
  nodeId: string
  nodeName: string
  input?: unknown
  output?: unknown
  error?: ExecutionError
  steps: TaskResult[]  // 每个步骤的详细状态
  startedAt: string
  finishedAt: string
}
```

### 3. Pipeline 失败策略
Node 新增 `failurePolicy` 字段：
- `fail_fast`（默认）：必需步骤失败立即停止
- `continue`：继续执行，返回 partial_failure
- `retry_then_continue`：重试后决定（预留）

### 4. 确定性触发
Node 新增 `triggerMode` 字段：
- `agent`：只能由 Agent 自动触发
- `explicit`：只能通过 API/命令/按钮触发
- `both`（默认）：两种方式都支持

新增 API：
```bash
# 直接运行 Node
POST /api/tohelper/node/run
{
  "nodeId": "node-xxx",
  "input": {"input": "查询优惠券"}
}

# 校验配置
GET /api/tohelper/config/validate
```

## 关键设计原则

1. **Agent 自主选择** 只负责"是否调用"
2. **显式命令和 UI 按钮** 负责"确定调用"
3. **Pipeline** 按固定配置执行，不让 LLM 决定是否跳过 Task
4. **Node description** 只是提示信息，不是路由规则
5. **失败状态** 必须准确传播，不能混入普通文本
