# Node — Workflow as Tool

## 定位

Node 是 tohelper 的第二核心功能：让用户在 UI 中**定义可复用的执行单元**（Node），每个 Node 预配置了 LLM、工具集、system prompt 等参数。定义完成后，Node 作为一种 tool 类型，在 **Tool 面板中统一装配**到当前对话使用。

核心理念：**一切皆 Tool**。无论是 builtin、MCP、skill、Node 还是未来的 Workflow，最终都以 tool 的形式出现在 Tool 面板中，由用户选择装配到 DSH 对话。

## 整体工具体系

```
Tool 面板（统一装配界面）
├── Builtin Tools    — DSH 内置工具（read_file, write, grep...）
├── MCP Tools        — 外部 MCP server 提供的工具
├── Skill Tools      — 技能文档工具
├── Node Tools       — 用户在 Node 面板定义的单执行单元
└── Workflow Tools   — 用户在 Workflow 面板编排的多 Node 组合（Phase 3）
```

**面板分工：**
- **Node 面板**：Node 的 CRUD（创建、编辑、删除）— 定义"是什么"
- **Tool 面板**：所有工具的统一装配/卸载 — 决定"用不用"

## 用户视角流程

```
1. 用户点击悬浮按钮 → 出现行星子菜单 → 点击 "Node"
2. 打开 Node 面板 → 创建一个 Node：
   - 名称：code_reviewer
   - 描述：代码审查专家，给出详细修改建议
   - System Prompt：你是一位资深代码审查工程师...
   - LLM：deepseek-v4（或使用当前对话默认）
   - 可用工具：[read_file, grep, mcp__github__get_pr]
   - 输入参数：{ file_path: string, focus?: string }
3. 回到 Tool 面板 → 在 "Node Tools" 分类下看到 code_reviewer
4. 点击"装配" → Node 注册为当前 agent 的一个 tool
5. 用户在对话中说："帮我审查 src/index.ts，重点看错误处理"
6. Agent 识别并调用 code_reviewer tool
7. Node 执行：用预配置的 LLM + 工具 + prompt 完成工作
8. 结果返回主对话
```

## 为什么是 "Tool" 而不是独立引擎

| Workflow as Tool | 独立工作流引擎 |
|---|---|
| 利用 DSH 已有的 tool 系统（注册、调用、权限） | 需要自己实现执行引擎 |
| 编排由主 agent LLM 智能决定 | 需要自己实现 DAG/状态机 |
| 用户装配多个 Tool 后可自由组合 | 需要预定义固定的连线 |
| 单 Node 即可使用，渐进复杂度 | 必须理解工作流概念才能上手 |
| 结果自然进入对话上下文 | 需要额外的结果路由机制 |
| 统一的装配入口，用户心智模型简单 | 不同类型工具需要不同管理方式 |

## 面板职责对比

| | Tool 面板 | Node 面板 | Workflow 面板（future） |
|---|---|---|---|
| **核心动作** | 装配/卸载 tool 到当前对话 | 创建/编辑/删除 Node 定义 | 编排多个 Node 为 Workflow |
| **操作对象** | 所有类型的 tool | Node 配置（LLM + tools + prompt） | Node 组合 + 连线 |
| **影响范围** | 当前 agent 的工具可见性 | 持久化的定义库 | 持久化的定义库 |
| **产出** | agent 可调用的 tool 集合 | 一条 node tool 出现在 Tool 面板 | 一条 workflow tool 出现在 Tool 面板 |

## 技术依赖

| DSH API | 用途 |
|---|---|
| `agent.ctx.tools.register()` | 将 Node 注册为 agent scope 的 tool |
| `ctx.llm.prepareCall()` + `stream()` | Node 执行时调用配置的 LLM |
| `ctx.tools.schemas()` | 列出可选工具（供 Node 配置 + Tool 面板展示） |
| `ctx.agents.create()` | （可选）复杂 Node 用子 agent 执行 |
| `ctx.webServer.register()` | Node CRUD + 装配 API 路由 |
| `agent.ctx.tools.restrict()` | 控制 builtin/MCP 工具可见性（已有） |

## 分阶段计划

| 阶段 | 目标 |
|---|---|
| **Phase 1**（本次） | Node CRUD + Tool 面板统一装配 + direct LLM 执行 |
| Phase 2 | Node 内多步 tool use（子 agent 模式） |
| Phase 3 | Workflow 定义 + 多 Node 编排 + 作为 workflow tool 装配 |
| Phase 4 | 条件分支 + 循环 + HITL |
