# Node-Task 架构重构完成

## 🎯 重构目标

将架构简化为两个核心概念：
- **Task**：LLM + Tools + TaskPrompt = 执行单元
- **Node**：LLM + Tasks[] + Mode + NodePrompt = 任务编排

## ✅ 已完成的工作

### 1. 类型定义重构

#### 新的 TaskConfig
```typescript
interface TaskConfig {
  id: string
  name: string
  description?: string
  
  // 核心字段
  taskPrompt: string              // Task 的任务提示词
  tools: string[]                 // Task 可用的工具列表（支持多个）
  
  // 可选配置
  llm?: LLMSlot                   // 独立 LLM 配置
  outputFormat?: 'text' | 'json'
  userPromptTemplate?: string
}
```

**关键变化**：
- ❌ 移除 `type` 字段（llm-call/tool-call/transform）
- ❌ 移除 `config` 嵌套结构
- ✅ 添加 `taskPrompt`（替代 systemPrompt）
- ✅ 添加 `tools[]`（支持多个工具）
- ✅ 保留 `llm` 可选字段（支持独立配置）

#### 新的 NodeConfig
```typescript
interface NodeConfig {
  id: string
  name: string
  description?: string
  
  // 核心字段
  nodePrompt: string              // Node 的任务描述
  llm: LLMSlot                    // Node 级别的 LLM（必需）
  mode: 'direct' | 'pipeline' | 'loop'  // 执行模式
  
  // 任务列表
  tasks: TaskConfig[]
  tools: string[]                 // Node 级别工具
  
  // Schema
  inputSchema?: object
  outputSchema?: object
  
  // 元数据
  createdAt: string
  updatedAt?: string

```

**关键变化**：
- ❌ 移除 `executionMode`
- ❌ 移除 `systemPrompt`（direct 模式专用）
- ✅ 添加 `nodePrompt`（统一的任务描述）
- ✅ 添加 `mode`（三种模式：direct/pipeline/loop）
- ✅ `llm` 变为必需字段

### 3. 新执行器架构

**文件**：`src/host/node/executor-v2.ts`

```typescript
export class NodeExecutor {
  async run(input: unknown): Promise<NodeExecutionResult>
  
  // 三种执行模式
  private async runDirect(input: unknown)
  private async runPipeline(input: unknown)
  private async runLoop(input: unknown)
  
  // Task 执行
  private async runTask(task: TaskConfig, input: unknown)
  
  // Loop 模式决策
  private async decideNextStep(context: any): Promise<LoopDecision>
}
```

#### Direct 模式
```typescript
async runDirect(input) {
  const task = nodeConfig.tasks[0]
  const result = await this.runTask(task, input)
  return { output: result.output }
}
```

#### Pipeline 模式
```typescript
async runPipeline(input) {
  let currentInput = input
  for (const task of nodeConfig.tasks) {
    const result = await this.runTask(task, currentInput)
    currentInput = result.output
  }
  return { output: currentInput }
}
```

#### Loop 模式（核心创新）⭐
```typescript
async runLoop(input) {
  let context = { input, history: [], completed: [] }
  
  while (iteration < maxIterations) {
    // LLM 决定下一步
    const decision = await this.decideNextStep(context)
    
    if (decision.action === 'done') {
      return { output: decision.result }
    }
    
    // 执行选定的 Task
    const task = findTask(decision.taskId)
    const result = await this.runTask(task, context.input)
    context.input = result.output
  }
}
```

**Loop 决策提示词**：
```
你是任务调度专家。根据以下信息决定下一步：
- nodePrompt: 用户的任务目标
- availableTasks: 可用的任务列表
- context: 当前执行上下文

决策选项：
- execute: 选择一个 Task 执行
- done: 任务完成，返回结果

输出 JSON 格式：
{
  "action": "execute" | "done",
  "taskId": "task-xxx",
  "result": {},
  "reasoning": "决策理由"
}
```

## 📊 架构对比

### 旧架构
```
Task (type + config)
├── type: 'llm-call' | 'tool-call' | 'transform'
└── config: { systemPrompt, toolName, ... }

Node (executionMode + systemPrompt/tasks)
├── executionMode: 'direct' | 'pipeline'
├── systemPrompt (direct 模式)
└── tasks (pipeline 模式)
```

### 新架构
```
Task (taskPrompt + tools + llm)
├── taskPrompt: string
├── tools: string[]
└── llm?: LLMSlot

Node (nodePrompt + mode + llm + tasks)
├── nodePrompt: string
├── mode: 'direct' | 'pipeline' | 'loop'
├── llm: LLMSlot
└── tasks: TaskConfig[]
```

## 🎯 核心优势

1. **概念简化**
   - Task 统一为 `LLM + Tools + Prompt`
   - 移除 type 字段，减少复杂度

2. **灵活配置**
   - Task 可配置多个 tools
   - Task 可独立配置 LLM
   - Node 和 Task 都有明确的 prompt

3. **强大编排**
   - Direct 模式：单任务
   - Pipeline 模式：顺序执行
   - Loop 模式：智能调度（核心创新）

4. **易于理解**
   - `nodePrompt` 描述整体目标
   - `taskPrompt` 描述具体任务
   - Mode 决定执行方式

5. **向后兼容**
   - 保留旧类型定义（标记 deprecated）
   - 提供迁移工具
   - 支持新旧编辑器切换

```json
    },
    {
      "id": "task-2",
      "name": "数据清洗",
      "taskPrompt": "清洗异常数据和缺失值",
      "tools": ["cleaner", "imputer"]
    },
    {
      "id": "task-3",
      "name": "统计分析",
      "taskPrompt": "计算关键统计指标",
      "tools": ["stats-calculator"]
    },
    {
      "id": "task-4",
      "name": "数据可视化",
      "taskPrompt": "生成可视化图表",
      "tools": ["chart-generator"]
    },
    {
      "id": "task-5",
      "name": "报告生成",
      "taskPrompt": "整合分析结果生成报告",
      "tools": ["report-writer"]
    }
  ],
  "tools": []
}
```

**Loop 模式执行流程**：
1. LLM 分析 nodePrompt："分析销售数据并生成完整报告"
2. 决策：先执行 task-1（数据加载）
3. 执行完成后，决策：执行 task-2（数据清洗）
4. 继续决策：执行 task-3（统计分析）
5. 继续决策：执行 task-4（可视化）
6. 最后决策：执行 task-5（报告生成）
7. 完成，返回最终报告
