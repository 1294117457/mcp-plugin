# 开发步骤

## 总体顺序

```
Step 1: 目录结构重构（迁移现有代码，不加新功能）
Step 2: Host — Node 配置持久化
Step 3: Host — Node 装配/卸载逻辑
Step 4: Host — Node 执行引擎
Step 5: Host — Node API 路由 + /tools 接口改造
Step 6: Client — API 层 + 共享类型
Step 7: Client — Home 改造（行星菜单）
Step 8: Client — Tool 面板改造（统一分组 + Node 装配）
Step 9: Client — NodePanel + NodeList + NodeEditor
Step 10: 联调 + 端到端验证
```

---

## Step 1: 目录结构重构

**目标**：将现有代码迁移到新目录结构，功能不变。

**操作清单：**

1. 创建目录：
   ```
   src/host/
   src/host/tool/
   src/host/node/
   src/client/api/
   src/client/home/
   src/client/tool/
   src/client/node/
   src/client/shared/
   ```

2. 迁移 host 代码：
   - `src/index.ts` → 拆分到 `src/host/index.ts` + `src/host/agent-tracker.ts` + `src/host/tool/index.ts` + `src/host/tool/routes.ts` + `src/host/util.ts`
   - `src/config.ts` → `src/host/tool/config.ts`（文件路径改为 `data/tool-config.json`，需兼容旧文件名）

3. 迁移 client 代码：
   - `src/client/components/FloatingButton.tsx` → `src/client/home/FloatingButton.tsx`
   - `src/client/components/App.tsx` → `src/client/home/index.tsx`（暂保持原逻辑）
   - `src/client/components/Panel.tsx` → `src/client/tool/ToolPanel.tsx`
   - `src/client/components/ToolsTab.tsx` → `src/client/tool/ToolsTab.tsx`
   - `src/client/components/McpTab.tsx` → `src/client/tool/McpTab.tsx`
   - `src/client/components/SkillsTab.tsx` → `src/client/tool/SkillsTab.tsx`
   - `src/client/api.ts` → `src/client/api/tool.ts`
   - `src/client/styles.ts` → `src/client/shared/styles.ts`

4. 更新引用：
   - `src/client/entry.tsx` 中 import 路径
   - `vite.config.ts` 中 entry 路径（如果变了）
   - `package.json` 中 `main` 字段

5. 更新 tsconfig：
   - `tsconfig.host.json` include 路径
   - `tsconfig.json` include 路径

6. **验证**：`npm run build` 通过 + 手动测试现有功能正常

## Step 2: Host — Node 持久化

**目标**：实现 `src/host/node/config.ts`。

**交付物：**
- `loadNodeConfig()` / `saveNodeConfig()`
- 自动迁移：首次加载时如果不存在则创建空文件
- atomic write（与 tool config 相同模式）

**验证**：单元测试或手动调用确认读写正确。

---

## Step 3: Host — Node 装配/卸载

**目标**：实现 `src/host/node/index.ts` 中的 `equipNode` / `unequipNode`。

**关键逻辑：**
- `equipNode(nodeId)` → 从 config 读取 NodeConfig → 调用 `agent.ctx.tools.register()` → 记录 disposer
- `unequipNode(nodeId)` → 调用 disposer → 从 equipped 移除
- agent 生命周期处理：`agent/disposed` 清理，`agent/created` 重新装配

**验证**：通过 API 装配后，`GET /api/tohelper/tools` 能看到新注册的 node tool。

---

## Step 4: Host — Node 执行引擎

**目标**：实现 `src/host/node/executor.ts`。

**Phase 1 范围（direct 模式）：**
- 接收 `(nodeConfig, args)` → 组装 messages → `ctx.llm.prepareCall()` → `stream()` → 收集文本 → 返回
- 超时处理：默认 120s
- 错误处理：LLM 调用失败时返回错误描述

**不含（Phase 2）：**
- 子 agent 创建
- Node 内 tool use
- 多轮对话

**验证**：手动调用 executor.run() 或通过装配后在对话中触发 tool call。

---

## Step 5: Host — Node API 路由 + /tools 改造

**目标**：实现 `src/host/node/routes.ts` + 改造现有 `/api/tohelper/tools` 接口。

**Node 路由列表：**
- `GET /api/tohelper/node/list` — 列出 Node 定义
- `POST /api/tohelper/node/create` — 创建
- `POST /api/tohelper/node/update` — 更新
- `POST /api/tohelper/node/delete` — 删除
- `POST /api/tohelper/node/equip` — 装配（Tool 面板调用）
- `POST /api/tohelper/node/unequip` — 卸载（Tool 面板调用）

**改造 /api/tohelper/tools：**
- 响应中新增 `node` 数组，列出所有已定义 Node + equipped 状态
- 前端 Tool 面板据此展示所有类型 tool 的统一视图

**校验逻辑：**
- name 格式校验
- name 冲突检测（vs builtin + MCP + 其他 node）
- required 字段检查

**验证**：curl / httpie 手动调用每个 API 确认行为正确。

## Step 7: Client — Home 改造

**目标**：将现有的"点击按钮直接打开面板"改为"点击按钮展开行星菜单"。

**操作：**
1. 创建 `SatelliteMenu.tsx`
2. 改造 `home/index.tsx`（原 App.tsx）的状态逻辑
3. FloatingButton 的 onToggle 改为打开菜单而非直接打开面板

**验证**：点击主按钮出现子按钮动画，点击 Tool 子按钮打开原有面板。

---

## Step 8: Client — Tool 面板改造

**目标**：将 Tool 面板改为统一装配界面，按来源分组展示所有 tool。

**改造内容：**
- 新增 `ToolsAllTab.tsx`：统一分组展示 builtin / MCP / skill / node
- 每组内的 tool 都有装配/卸载 toggle
- Node 类型的装配调用 `/node/equip`，Builtin/MCP 类型调用 `/mcp/deny`
- MCP 管理（server 增删）拆为独立 tab（不影响装配逻辑）

**验证**：
- Tool 面板能看到 Node 分组
- 通过 API 创建的 Node 出现在 Node 分组中
- 点击装配后，Node 在对话中可被 agent 调用

---

## Step 9: Client — NodePanel + NodeList + NodeEditor

**目标**：实现 Node 定义管理面板（纯 CRUD，不含装配）。

**NodeList 功能：**
- 显示所有已定义 Node
- 显示配置摘要（LLM、tools 数量）
- 编辑/删除按钮
- "创建节点"按钮（跳转到 editor）
- 提示文字："创建后可在 Tool 面板中装配使用"

**NodeEditor 表单字段：**
- name（text input）
- description（text input）
- systemPrompt（textarea）
- llm provider + model（两个 input 或 select）
- tools（checkbox 列表，从 /tools API 拉取可选项）
- inputSchema（JSON textarea + 校验）

**验证**：能通过表单创建 Node，创建后在 Tool 面板的 Node 分组中出现。

---

## Step 10: 联调

**端到端验证场景：**

1. 打开 tohelper → 行星菜单 → 点击 "Node"
2. 在 Node 面板创建一个 "translator" Node
   - 配置：system prompt = "你是翻译助手"，inputSchema = `{ text, target_lang }`
3. 关闭 Node 面板 → 行星菜单 → 点击 "Tool"
4. 在 Tool 面板的"节点工具"分组中看到 translator
5. 点击装配 → 确认显示"已装配"
6. 在主对话中输入："帮我把 hello world 翻译成中文"
7. 确认 agent 调用了 translator tool
8. 确认收到翻译结果

## 风险点和注意事项

| 风险 | 应对 |
|---|---|
| `ctx.llm` 可能未就绪（provider 未注册） | executor 中 try-catch，返回清晰错误信息 |
| agent 切换时装配丢失 | `agent/created` 监听中自动重装配 |
| Node name 与动态注册的 MCP tool 冲突 | 装配时实时检查，冲突则拒绝并提示 |
| inputSchema 填写错误导致 agent 无法调用 | 创建时做基本 JSON Schema 校验 |
| LLM stream 超时 | executor 中设置 AbortSignal.timeout(120s) |
| config 文件从旧格式迁移 | 首次加载时检测旧 `data/config.json`，自动重命名为 `data/tool-config.json` |
