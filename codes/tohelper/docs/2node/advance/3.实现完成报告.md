## 使用示例

### 示例 1: 创建 Simple Node (Direct 模式)

```json
{
  "name": "text_translator",
  "description": "Translate text to English",
  "executionMode": "direct",
  "systemPrompt": "You are a professional translator. Translate the user's input to English.",
  "llm": {
    "provider": "deepseek-official",
    "model": "deepseek-chat",
    "temperature": 0.3
  },
  "inputSchema": {
    "type": "object",
    "properties": {
      "text": { "type": "string" }
    }
  },
  "outputSchema": {
    "type": "object",
    "properties": {
      "result": { "type": "string" }
    }
  }
}
```

**使用流程**：
1. 打开 tohelper 悬浮按钮
2. 点击"节点"
3. 点击"+ 创建节点"
4. 填写基础信息
5. 选择 "Direct" 模式
6. 填写 System Prompt 和 LLM 配置
7. 保存
8. 点击"装配"
9. 在对话中使用：`帮我用 text_translator 翻译"你好世界"`

---

### 示例 2: 创建 Complex Node (Pipeline 模式)

```json
{
  "name": "code_analyzer",
  "description": "Analyze code file for security issues",
  "executionMode": "pipeline",
  "tasks": [
    {
      "id": "task-read",
      "name": "Read File",
      "type": "tool-call",
      "config": {
        "toolName": "read_file"
      }
    },
    {
      "id": "task-analyze",
      "name": "Security Analysis",
      "type": "llm-call",
      "config": {
        "systemPrompt": "You are a security expert. Analyze code for vulnerabilities.",
        "outputFormat": "text"
      }
    }
  ],
  "tools": ["read_file"],
  "inputSchema": {
    "type": "object",
    "properties": {
      "filepath": { "type": "string" }
    }
  },
  "outputSchema": {
    "type": "object",
    "properties": {
      "result": { "type": "string" }
    }
  }
}
```

**使用流程**：
1. 打开 tohelper 悬浮按钮
2. 点击"节点"
3. 点击"+ 创建节点"
4. 填写基础信息
5. 选择 "Pipeline" 模式
6. 添加 Task 1：Tool Call (read_file)
7. 添加 Task 2：LLM Call (分析代码)
8. 在"允许的工具"中勾选 read_file
9. 保存
10. 点击"装配"
11. 在对话中使用：`帮我用 code_analyzer 分析 src/auth.ts`

**执行流程**：
```
用户输入: { filepath: "src/auth.ts" }
  ↓
Task 1 (tool-call): read_file("src/auth.ts")
  ↓ 输出: "file content..."
Task 2 (llm-call): 分析代码安全问题
  ↓ 输出: "发现 3 个安全问题：..."
```

## 技术亮点

### 1. 不侵入 dsh
- 完全基于 Cordis 插件机制
- 只使用 dsh 公开 API（ctx.llm, ctx.tools）
- 通过 `cordis.patch.yml` 加载

### 2. Task 系统设计
- 基于 Registry 模式，易于扩展
- 类型安全（完整的 TypeScript 类型定义）
- Pipeline 状态管理（Task 间共享数据）
- 详细的执行日志（调试友好）

### 3. 灵活的配置
- LLM 配置层级：Task > Node > Default
- Tool 白名单机制（安全性）
- 输入/输出映射（Tool Call Task）
- 变量替换（LLM Call Task）

### 4. 用户体验
- 渐进式 UI（从简单到复杂）
- 实时验证和错误提示
- 可折叠的 Task 编辑器
- 响应式布局
