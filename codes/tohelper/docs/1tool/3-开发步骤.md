## Step 2: 实现 discovery.ts

实现顺序：先让工具发现跑通。

1. 导入 `Context` 类型
2. 实现 `listAllTools(ctx)` — 调用 `ctx.tools.schemas()` 并转为 `ToolInfo[]`
3. 实现 `toolExists(ctx, name)` — 简单的 `.find()` 查询
4. 实现 `searchTools(ctx, keyword)` — `includes` 过滤
5. 实现 `suggestSimilar(ctx, name)` — 简单前缀或子串匹配

**验证**：在 `index.ts` 的 `apply` 中临时 `console.log(listAllTools(ctx))` 确认能拿到工具列表。

## Step 3: 实现 assembly.ts

1. 创建 `WeakMap<Agent, AssemblyState>` 存储
2. 实现 `getState(agent)` — get or create
3. 实现 `equipTools(ctx, agent, names)`:
   - 校验每个 name 是否存在（调用 discovery.toolExists）
   - 更新 Set
   - dispose 旧 restriction
   - 调用 `agent.ctx.tools.restrict({ allow: [...set] })`
   - 保存新 disposer
4. 实现 `equipOnly` — 同上但替换语义
5. 实现 `unequipTools` — 从 Set 删除 + 重新 restrict
6. 实现 `unequipAll` — dispose + 清空
7. 实现 `getEquipped` — 返回 Set 或 undefined

**验证**：手动调用 equipTools 后，检查 `ctx.tools.schemas(agent)` 返回的列表是否减少。

## Step 4: 实现 index.ts 命令注册

1. 注册 `/tools` 命令
   - 解析参数（`--equipped` / `--mcp` / keyword）
   - 调用 `listAllTools` + `getEquipped` 格式化输出
   - 返回 `{ kind: 'success', text }`

2. 注册 `/equip` 命令
   - 解析参数（`--only` / `--all` / names）
   - 调用 `equipTools` 或 `equipOnly` 或 `unequipAll`
   - 返回结果文本

3. 注册 `/unequip` 命令
   - 解析参数（`--all` / names）
   - 调用 `unequipTools` 或 `unequipAll`
   - 返回结果文本

## 踩坑预判

| 可能问题 | 原因 | 解法 |
|---|---|---|
| `ctx.commands` is undefined | `inject` 没声明 `'commands'` | 确保 `export const inject = ['commands', 'tools']` |
| `agent.ctx` is undefined | handler 拿到的 agent 可能类型不对 | 从 `invocation.agent` 获取，确认是 Agent 实例 |
| restrict 不生效 | 调用了 `ctx.tools.restrict` 而非 `agent.ctx.tools.restrict` | 必须在 agent 的 scoped context 上调用 |
| `/equip` 后 schemas 没变 | disposer 没正确管理 | 检查是否先 dispose 旧的再 apply 新的 |
| 工具列表为空 | `schemas()` 需要 Loader 加载完成 | 正常情况下 `inject: ['tools']` 保证了时序 |
| MCP 工具看不到 | MCP server 配置未加载 | 确认 profile 中有 `dsh-mcp-client` 实例 |
| tsx 不支持绝对路径 | Windows 路径分隔符 | cordis.patch.yml 中用正斜杠 `/` |
