# Phase 1 架构设计

## 目录结构

```
tohelper/
├── package.json
├── tsconfig.json
├── cordis.patch.yml          # 声明插件挂载
├── src/
│   ├── index.ts              # 主入口：注册命令 + 编排逻辑
│   ├── discovery.ts          # 工具发现：读取全量工具列表
│   ├── assembly.ts           # 装配状态管理：per-agent restrict 控制
│   └── types.ts              # 类型定义
└── docs/                     # 本文档目录
```

## 核心数据流

```
用户输入 /tools
    ↓
ctx.commands.execute(agent, '/tools ...')
    ↓
handler 调用 discovery.listAll(ctx)
    ↓
ctx.tools.schemas(/* global, 无 scope 过滤 */) → 全量 ToolSchema[]
    ↓
格式化输出：名称 + 描述 + 来源 + 是否已装配
    ↓
返回 CommandResult { kind: 'success', text }
```

```
用户输入 /equip read_file write grep
    ↓
handler 解析工具名列表
    ↓
assembly.equip(agent, names)
    ↓
1. 校验：names 中每个是否存在于全局注册表
2. 更新内存状态：equippedMap.get(agent) → Set<string>
3. dispose 旧 restriction → apply 新 restrict({ allow: [...set] })
    ↓
返回 CommandResult { kind: 'success', text: '已装配: ...' }
```

```
下一次 agent step
    ↓
agent-loop → systemPrompt.assemble(assembleContextFor(agent, signal))
    ↓
ToolRuntime.wireSchemas(agent) → 读 agent scope 的 restriction
    ↓
只返回 allow 列表中的 tool schemas → 进入 LLM request
    ↓
模型只看到已装配的工具
```

## 关键 API 映射

| 需求 | harness API | 说明 |
|---|---|---|
| 注册用户命令 | `ctx.commands.register({ name, handler })` | 返回 disposer |
| 获取全量工具 | `ctx.tools.schemas()` | 无 scope 参数 = 全局视图 |
| 获取 agent 当前可见工具 | `ctx.tools.schemas(agent)` | 含 restrict 过滤后的视图 |
| 过滤 agent 可见工具 | `agent.ctx.tools.restrict({ allow: string[] })` | 返回 disposer，调用 disposer 移除限制 |
| 判断工具来源 | `schema.name.startsWith('mcp__')` | MCP 工具固定前缀 `mcp__<server>__<tool>` |
| 监听工具集变化 | `ctx.on('tools/change', cb)` | 工具注册/注销/restrict 变化时触发 |

## 状态管理

Phase 1 的装配状态**仅在内存中**，不持久化：

```ts
// assembly.ts 核心状态
interface AssemblyState {
  equipped: Set<string>         // 当前装配的工具名集合
  restrictDisposer?: () => void // 当前 restrict 的 disposer
}

// 按 agent 隔离
const stateMap = new WeakMap<Agent, AssemblyState>()
```

- 新对话 = 新 agent = 无 restriction（默认全部可见）
- 用户 `/equip` 后，agent 只看到指定工具
- 用户 `/unequip --all` 可恢复全部可见
- agent 生命周期结束时 WeakMap 自动释放

## 命令设计

### `/tools` — 列出工具

```
/tools              列出全部工具及装配状态
/tools --equipped   只列出已装配的
/tools --mcp       只列出 MCP 来源的
/tools <keyword>   按名称/描述模糊搜索
```

输出格式：
```
[✓] read_file       — Read a file from disk.
[✓] write           — Write content to a file.
[ ] grep            — Search file contents with regex.
[ ] mcp__github__search_repositories [MCP] — Search GitHub repos.
---
已装配 2/4 个工具
```

### `/equip` — 装配工具

```
/equip read_file write grep     追加装配（保留已有）
/equip --only read_file write   精确设定（替换已有）
/equip --all                    装配全部（等同移除 restrict）
```

### `/unequip` — 卸载工具

```
/unequip grep                   移除指定工具
/unequip --all                  移除全部限制，恢复默认（全部可见）
```

## 边界情况处理

| 场景 | 行为 |
|---|---|
| `/equip` 一个不存在的工具名 | 返回错误提示 + 列出近似名 |
| `/equip` 后 MCP server 新注册了工具 | 新工具不自动进入 allow 列表（需手动 equip） |
| MCP server 断开，已装配的 MCP 工具消失 | restrict 中仍保留该名称，但 schemas 中不会出现（无副作用） |
| 对话中途 agent scope 销毁 | WeakMap 自动释放，restrict disposer 由 cordis effect 清理 |
| 用户从未执行 /equip | 无 restriction，全部工具可见（默认行为不变） |
