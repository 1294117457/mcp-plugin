# tohelper — 动态工具装配插件

## 定位

tohelper 是一个 dsh 外部插件，让用户在对话中**手动选择**哪些工具对当前 agent 可见。核心场景：

1. 列出所有已注册工具（harness 内置 + MCP 外部）
2. 用户通过命令或 UI 选择装配/卸载工具
3. 只有已装配的工具出现在 agent 的 system prompt，agent 只能调用这些工具

## 为什么需要

默认情况下 dsh 会把 **所有注册的工具** 暴露给 agent。工具越多：
- system prompt 越长 → token 消耗高
- 模型选择噪音大 → 调用准确率下降
- 不相关工具出现在提示中 → 干扰模型推理

tohelper 让用户针对当前任务只装配需要的工具子集。

## 分阶段实现

| 阶段 | 目标 | 核心能力 |
|---|---|---|
| **Phase 1**（本次） | 读取已有工具 + 命令选择装配 | `/tools` 列表 + `/equip` + `/unequip` + restrict |
| Phase 2 | MCP 外部工具动态接入 | 运行时添加 MCP server + 工具发现 |
| Phase 3 | Web UI 选择面板 | Client 插件 + slot 注册 + React 组件 |
| Phase 4 | 持久化 + 预设 | SessionEvent 持久化 + 工具组预设 |

## 技术栈

- Host 端：纯 Cordis 插件，依赖 `ctx.commands` + `ctx.tools`
- 无 HTTP 路由（Phase 1 不需要 web API）
- 无 Client 端（Phase 1 仅命令交互）
- 运行方式：`--patch` overlay 开发模式

## 与 harness 的关系

tohelper **不修改** harness 代码。它是一个独立 npm 包，通过 `cordis.patch.yml` 挂载到 dsh 的 Loader 树中。使用的全部是 harness 已有的公开扩展点：

| 扩展点 | 用途 |
|---|---|
| `ctx.commands.register()` | 注册 `/tools`、`/equip`、`/unequip` 命令 |
| `ctx.tools.schemas()` | 发现所有已注册工具 |
| `agent.ctx.tools.restrict({ allow })` | 过滤 agent 可见工具 |
| `ctx.systemPrompt.context()` | 告诉模型当前装配状态（可选） |
